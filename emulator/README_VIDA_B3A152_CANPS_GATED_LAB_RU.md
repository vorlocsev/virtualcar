# B3A152: управляемая поддержка J2534-2 CAN_PS для проверки VIDA ReadVin

## Подтверждённая причина B3A151

В исходном журнале владельца для единственного сеанса B3A146 (из 42 браузерных
инициализаций) обнаружены `PassThruOpen=1`, `PassThruConnect=1`, но
`APP_TX=0`, `RX_DELIVERED=0`, `CEM_40/B9FB=0`.
Фактический ответ на `PassThruConnect(0x8004,0x100,125000,...)`:
**3 = ERR_INVALID_PROTOCOL_ID**. DLL той сборки поддерживала только J2534-1
`CAN=5` и `ISO15765=6`. Значит, драйвер прерывал обмен до первого
запроса CEM; синтетические 13 кадров B3A146 не были запрошены.
Это подтверждение ошибки совместимости протокола, **не** успешного VIN.

## Реализация

Перенесён строго ограниченный транспортный контракт из существующего draft
PR #319 в текущий `development` без остальных ~78 коммитов PR #319.

- `[Diagnostics] EnableVidaCanPsLab=1` отдельно разрешает J2534-2
  `CAN_PS=0x8004`, `ISO15765_PS=0x8005`. По умолчанию **0**.
- Для PS допускаются только `125000` бит/с и биты `flags`, входящие
  в `CAN_29BIT_ID=0x100`. Остальные vendor ProtocolID не алиасируются.
- `channel.protocol` остаётся внутренним `CAN=5` или `ISO15765=6`;
  `channel.wire_protocol` отдельно хранит J2534-2 ID. RX, TX, periodic,
  диагностические контексты и фильтры используют **wire ID** там, где
  это ожидается вызывающей стороной.
- `SET_CONFIG(J2534_PINS=0x8001, value=0x030B)` записывает
  **только виртуальную конфигурацию** MS-CAN контактов 3/11. Реального
  переключения пинов, аппаратного DiCE, реле или CAN-трансивера нет.
  До этой настройки PS TX и RX-фильтры отклоняются `ERR_PIN_INVALID`;
  фоновая синтетика/трасса тоже не передаётся в PS RX.
- Неверный набор `J2534_PINS` -> `ERR_PIN_INVALID`.
  Другая скорость PS в `SET_CONFIG` -> `ERR_INVALID_BAUDRATE`.
  Весь список `SET_CONFIG` сначала валидируется; частичных изменений нет.
- Несовпадение `PASSTHRU_MSG.ProtocolID` либо фильтра с wire ID
  отклоняется. Существующие обычные J2534-1 каналы сохраняют прежние
  маршруты, а синтетические ответы CEM не меняются.
- Никаких дополнительных ECU RX, VIN, K-Line keyword, B9F0 или OEM
  данных эта поправка не генерирует.

## Проверки

**Код host-тестов добавлен, но настоящий native x86 build, host suite,
exact-head GitHub CI и оригинальная VIDA в этой ветке пока не запускались.**
8 групп в `emulator/tests/virtualcar_test.c`:

1. Запрет при выключенном opt-in; отказ неизвестного 0x8006.
2. Отказ неправильной скорости/флагов; приём `0x8004/125000/0x100`.
3. Запрет TX и фильтров до настройки `J2534_PINS`.
4. Атомарный отказ неверных пинов и неверной скорости.
5. `J2534_PINS=0x030B`, `GET_CONFIG` и wire ProtocolID фильтра.
6. RX `ProtocolID=0x8004` на внутреннем маршруте CAN.
7. Изоляция TX с чужим ProtocolID и завершение канала.
8. Независимый `ISO15765_PS` канал, `RX.ProtocolID=0x8005`.

Стандартный воспроизводимый host-компилятор по существующей инструкции
репозитория (запускать в **отдельном** checkout ветки B3A152):

```bash
cd emulator
gcc -std=c11 -O2 -Wall -Wextra -o /tmp/virtualcar_test tests/virtualcar_test.c
/tmp/virtualcar_test
./build-cross.sh
```

Проверить SHA точно того checkout и не смешивать результаты со старой DLL.

## Следующий контрольный VIDA-gate

**Не активировать автоматически.** Владелец уже восстановил B3A135D через
`B3A146_ORIGINAL_STAGED_INI_RESTORED`. Тот старый DLL бинарник не
поддерживает `CAN_PS`, а добавление строки в существующий INI не
поможет. Нужны отдельно собранная и проверенная Windows x86 DLL из
B3A152, точная сверка её SHA и изолированная установка/резервное
копирование до единственного запуска оригинальной VIDA.

В изолированном INI **только новой DLL** включить
`[Diagnostics] EnableVidaCanPsLab=1` с заранее отдельно подготовленными
синтетическими 13 кадрами CEM_40/B9FB B3A146. В целевом сеансе
собрать приватный append-only журнал и проверить последовательность:

1. 0x8004 / 0x100 / 125000, `Connect status 0`.
2. `J2534_PINS = 0x030B` реально применён без ошибок.
3. Первый `APP_TX` появился в правильном браузерном процессе/канале.
4. Если есть `CEM_40/B9FB`: D2 response staged и RX действительно
   доставлены, 13 кадров сгруппированы по channel/generation.
5. Оригинальная VIDA самостоятельно приняла VIN (отдельная скриншотная
   приёмка). Введённый руками VIN НЕ считается ReadVin PASS.
6. После опыта восстановить исходную DLL и INI из независимых резервных копий.

Никакого утверждения об аутентичности Volvo XC90 V8 MY2009. Данные
B3A146 транспонированы из исторического лабораторного примера; часть полей
не согласована с целевым автомобилем, B9F0 остаётся отключённым.

**Источники:** отчёты владельца B3A147–B3A151, PR #319 и его реализация
`EnableVidaCanPsLab`, `emulator/src/virtualcar.c` базового `development`.
