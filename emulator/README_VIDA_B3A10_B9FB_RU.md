# Virtual Car B3A10: forensic-сравнение публичного B9FB и лабораторного VIN

Статус: **оффлайн-аудитор 8/8 PASS; подлинный B9FB именно XC90 V8 MY2009 не получен**. Никакие ответы ECU, CAN/ISO9141 пакеты, ключи FIVE_BAUD_INIT или VIN не добавлены в виртуальный J2534. Исходные журналы и файлы не меняются.

## Что установлено

Исходный опубликованный исторический DiCE B9FB содержит 13 кадров CAN J2534 `0x01200003`, после удаления 1-байтового заголовка каждого кадра — 91 байт: `50 F9 FB` и **88 байт B9FB**. VIN находится по смещению **11** в 88-байтовом блоке. Публичная версия содержит 17 `X` на месте VIN.

В CRLF-полях после бинарного префикса `57 00 30 66 70 28` обнаруживается 3-значное поле `295` (кандидат vehicle type) и шестизначное `198625` (кандидат chassis). Volvo Car Bookstore / VIDA указывает **XC90 P2 type 275**, **XC70 P2 type 295**. Однако позиционная расшифровка поля `295` именно в этом B9FB по независимой схеме не подтверждена. Это **важное несовпадение кандидата**, но не окончательная атрибуция происхождения.

В лабораторном INI 17 байтов публичного VIN заменены на `YV1CZ0002A0000001`. Его десятый символ `A` даёт модельный год **2010** по стандарту VIN, тогда как целевой автомобиль — MY2009 (`9`). Последние шесть VIN `000001` также расходятся с отдельным полем `198625`. Последние две проверки опираются на допущение, что отдельное шестизначное поле содержит шасси, поэтому выдаются как **конфликт кандидатных полей**, а не подтверждение схемы OEM.

Побайтовое сопоставление публичной redacted-версии и лабораторной 13-кадровой версии обнаруживает **ровно 17 изменённых байтов B9FB на смещениях 11..27**. Остальная 88-байтовая часть неизменна. Это подтверждает, что замена VIN не превратила донорский профиль в достоверный XC90 2009.

## Инструмент

`emulator/tools/audit_vida_b3a10_b9fb_identity.py`:
- Извлекает исходные J2534 `PassThruReadMsgs().Data` из отдельного **текстового DiCE** захвата; альтернативно читает только `D2_50.B9FBFrame*` из экспериментального INI.
- Проверяет однородный CAN ID, точный заголовок `8F 50 F9 FB`, последовательность D2, `4F` на последнем кадре и исходную длину 8-байтовых CAN кадров.
- Отделяет D2-перенос, кандидатные поля CRLF/тип/VIN/шасси и основание происхождения. **Никакого автоматического принятия идентичности.**
- Режим `--compare-ini` даёт только изменённые смещения и SHA256, не подставляя исходные байты в другое место. Результат всегда `replay_approved=false`.
- Выходной JSON не содержит VIN и полезной нагрузки ECU. Оригинальный источник не редактируется и не обезличивается.

Запуск из корня checkout:

```powershell
python emulator\tools\audit_vida_b3a10_b9fb_identity.py --source emulator\samples\p2_b9fb_public_redacted.txt --kind historical_public --compare-ini emulator\virtualcar-p2-b9fb-lab-vin.ini --out B3A10-comparison.json
python -m unittest discover -s emulator\tests -p test_audit_vida_b3a10_b9fb_identity.py -v
```

Сценарий `--out` создаёт только новый файл (откажет при существующем), не устанавливает J2534, не запускает VIDA/DiCE. Тестовые данные в `test_audit_vida_b3a10_b9fb_identity.py` транскрибированы из опубликованного исторического примера и проверяются локально; они **не** являются новым оригинальным захватом XC90.

## Следующий технический блокер

Нужно добыть оригинальный DiCE/J2534 захват из подтверждённого XC90 P2 V8 MY2009. Если он появится, сначала проверить его по B3A9 (источник, хеш строк, ECU/сеть/скорость/время) и B3A10 (D2 транспорт, согласованность полей), затем независимо подтвердить Vehicle ID. До этого **никаких ответов B9FB/B9F0, ключевых байтов FIVE_BAUD_INIT или фиктивного чтения VIN в релизной DLL**. PR #319 остаётся Draft.
