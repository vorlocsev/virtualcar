# B3A53: почему B9FB загрузился с нулевым числом кадров

Оригинальная VIDA в пользовательском frozen B3A47-сеансе завершила
`READ VEHICLE` ошибкой `No response from the vehicle`.

Проверки B3A50/B3A52:
- Все шесть D2 B9FB запросов однозначно сопоставлены: два
  `CEM_40/125000` и один `CEM_50/500000` дошли до отсутствующей
  фикстуры, три `CEM_50/250000` отклонены строгим маршрутизатором.
- Исторический лог штатной виртуальной DLL содержит `Active INI:`
  с тем же текстовым PID и 14 записей D2-фикстур.
- **CEM_40 и CEM_50 B9FB зарегистрировали ноль кадров**;
  подлинный ECU RX и положительный VIN отсутствуют.
- Текстовый PID не является самостоятельным доказательством загрузки
  DLL оригинальной VIDA. Нулевая загрузка сама по себе не различает
  отсутствие настройки и её отказ на этапе валидации.

## Проверка локальной конфигурации

`emulator/tools/audit_vida_b3a53_b9fb_loader.py` реализует
ограниченную аналогию проверок из `emulator/src/virtualcar.c`:
`parse_num`, `parse_hex`, `parse_frame8`,
`validate_d2_fixture` для двух базовых `B9FB`.

Диагностирует категории:
- `no_frame_count_declared`, `zero_frame_count`;
- `invalid_frame_count_falls_back_to_zero`, `frame_count_exceeds_native_limit`;
- `response_id_outside_29bit_range`;
- `missing_declared_frame`, `invalid_eight_byte_frame`;
- `invalid_d2_frame_sequence`;
- `locally_structural_negative_reply_not_vin`;
- `locally_structural_reply_not_oem_verified`.

Последние две категории означают **только локально распознанное D2
обрамление**. Они не доказывают реальную загрузку, физический CEM,
значение VIN, MY2009, правильную скорость или принятие VIDA.
При расхождении текущего INI с сохранённой инициализацией причина
нулевой исторической загрузки остаётся **NOT_VERIFIED**.
Парсер INI намеренно отклоняет неоднозначные секции и нестандартные
данные: он не утверждает стопроцентную эквивалентность Windows
`GetPrivateProfileStringA` для всех возможных INI.

С доверенного checkout можно запустить:

```powershell
py -3 .\emulator\tools\audit_vida_b3a53_b9fb_loader.py --ini "C:\PRIVATE\PATH\virtualcar.ini"
```

Подставить **свой действительный локальный путь**. Исходный файл
должен остаться конфиденциальным. Вывод содержит только фиксированные
категории, количество кадров 0..64 и индекс проблемного кадра,
без VIN, ответа CAN, PID, пути, хеша, байтов фикстур или иной
содержательной информации из профиля.

Для owner-only маршрута из уже проверенного B3A52 frozen window
предпочтительнее отдельно проверенный переносимый `Invoke-VirtualCar-B3A53-CurrentINI.py`:
он использует ту же приватную `Active INI` запись как **источник текущего пути**,
не передаёт путь третьим лицам и не делает вывод о прошлом содержимом
файла. Если файл с тех пор перемещён или отредактирован, сравнение
с исторической загрузкой невозможно.

**Ограничения:** никаких новых VIDA запросов, никакого физического
J2534, изменения native J2534 DLL, INI, ECU, прошивок, SecurityAccess,
донорских VIN или поддельных CEM ответов. `main`, публикации и
приватные исходники не меняются. #326 и #4 остаются OPEN.

## B3A59: офлайн-проверка ResponseId против документированного VIDA D2 RX-фильтра

На основе исследования `spnda/volvo_vida_db/scripts/d2.py` добавлен
**только статический** предзапусковый контроль к существующему B3A53-аудиту.

Для каждого маршрута `CEM_40` / `CEM_50` выводятся фиксированные категории:

- `response_id_source`: `native_default_response_id`,
  `explicit_hex_ini_response_id` или
  `malformed_ini_falls_back_to_native_default`.
- `vida2014d_d2_rx_filter_candidate`: `odd_extended_id_candidate`,
  `even_extended_id_mask_mismatch`,
  `width_unknown_without_j2534_flags` либо `not_evaluated`.
- `actual_j2534_d2_filter_and_29bit_flags_verified=false` всегда.

Фильтр исследованного VIDA 2014D в стороннем исходнике описан как
`mask/pattern=0x00000001` для нечётных 29-битных CAN ID. Наличие нечётного
`ResponseId` в локальном INI не доказывает, что оригинальная VIDA
создала такой фильтр, выбрала нужный канал и получила кадры. Значение
`not_evaluated` выдаётся, если фикстура не прошла существующую проверку
D2 или в INI отсутствуют пригодные кадры.

Проверка по-прежнему вызывается через прежнюю команду `--ini`;
отдельной установки или подключения ECU не требуется. Ни исходный
`ResponseId`, ни VIN, кадры, путь, PID или сырой дамп не выдаются.
Никакой конфигурации, DLL, скорости CAN и правила маршрутизации скрипт
не изменяет. Добавлены 8 независимых синтетических групп проверок.

Чтобы разблокировать оригинальную VIDA ReadVin, владелец отдельно
устанавливает **только приватно и явно** подготовленный синтетический
13-кадровый профиль, проверяет реальную загрузку B9FB в native DLL,
затем реальную доставку J2534 RX и итоговый ответ интерфейса VIDA.
Этот шаг данной статической проверкой не подменяется.
