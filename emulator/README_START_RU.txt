# SectorV Virtual Car v0.3.6.4 — исследование номера CEM и сеть ECU

Статус: **лабораторная Windows x86 сборка**, только чтение. В этом выпуске НЕ подтверждено обнаружение ECM/TCM/BCM в VDASH; ранее VDASH действительно отобразил VIN донорского XC90 V8 2005 при `EmitIsoRxStart=1`.

## 1. Номер CEM из Flash

В оригинальном 320-КиБ образе M30855 XC90 V8 2005 (поставлен пользователем) по смещению `0x4FF40` находится ASCII `30728539`, а по `0x4FF68` — `30728541`. В остальных четырёх образах M32C первое значение меняется (`30786476`, `30728542`, `30786475`, `30765148`), а второе остаётся `30728541`.

В диагностической таблице контрольного образа на смещении `0x0472E`: `F0 00 64 21 00 00 0F 00 07 00` — ID `00F0`, адрес `0x00002164`, поля `15` и `7`. Этот адрес **не попадает в область самого Flash** (предполагаемое отображение `0xFB0000..0xFFFFFF`). Вероятно, данные F0 формируются с использованием иной памяти или процедуры. Доказательства, что в реальном D2 `B9 F0` передаются именно эти 8-цифровые строки, пока нет.

Таблицы `00FB -> 0xFFA000` и `00FC -> 0xFFA100` адресуют 88-байтный блок vehicle information (с VIN) и 142-байтный блок конфигурации. Это **не один и тот же идентификатор**, что F0.

В последнем журнале SectorV спрашивал `22 F1 14` и `CB 50 B9 FB`, но не `CB 50 B9 F0`. Ошибка «не удалось получить номер CEM» не доказывает, что пропал ответ F0. Возможно, UI ожидает иной OEM-идентификатор.

В новом личном базовом профиле `D2_50_B9F0 FrameCount=0`. Ранее включённый трёхкадровый пример взят от **другого CEM** и больше не выдается за оригинальный ответ XC90 V8. Его байты оставлены только для исторического A/B в INI, но не активированы.

## 2. Начало виртуальной сети ECU

DLL расширена двумя независимыми режимами:

1. `D2_Node0` … `D2_Node7`: до восьми дополнительных адресов узлов, каждый со своим D2 `Target`, `Opcode` (`F0`, `FB`, `FC`), скоростью CAN (`125000`/`500000`), `ResponseId`, валидируемой последовательностью кадров `Frame0...`. **По умолчанию все выключены**. Узлы 0x40 и 0x50 зарезервированы за CEM, конфликтующие записи игнорируются, из соседнего блока не копируются выдуманные ответы.
2. `PassiveTrace`: до 12 реальных, заранее записанных 8-байтных CAN-кадров; для каждого задаются собственные `Id`, `Baud`, `PeriodMs`, `Data`. Воспроизведение включается только при явном `Enabled=1` и `Count`, строго на соответствующей скорости. По умолчанию отключено. Это не эмуляция всех модулей автомобиля и не доказательство OEM-подлинности трассы.

J2534-фильтры при воспроизведении сохраняются, `START_OF_MESSAGE` для VDASH сохранён. Никаких услуг записи, разблокировки, конфигурирования, удаления DTC или программирования не добавлено.

### Пример подключения *своих* измеренных данных

```ini
[PassiveTrace]
Enabled=0
Count=1

[Trace0]
Id=123
Baud=125000
PeriodMs=100
Data=00 00 00 00 00 00 00 00

[D2_Node0]
Enabled=0
Target=10
Opcode=F0
Baud=500000
ResponseId=01200003
FrameCount=0
; Frame0=... ; Frame1=...
```

Здесь `123` и нулевые байты исключительно **заглушки, не образец трафика Volvo**. Заменять на реальный захват и включать `Enabled=1` только после проверки направления, CAN-ID, скорости, порядка и содержания кадров. Протокол D2 других модулей может отличаться; нельзя переносить ответ CEM на ECM, TCM и BCM.

## 3. Как проверять

1. Распаковать **приватный XC90 2005 ZIP** в **новую папку**. Не смешивать DLL со старыми версиями.
2. Полностью закрыть VDASH и SectorV. Запустить `VirtualCarControl.exe` от администратора, нажать «Подготовить XC90 V8 2005».
3. Нажать «Начать тест», открыть VDASH, выбрать SectorV Virtual Car, подключиться. Ожидаем повторное распознавание VIN, но **список ECU пока может оставаться пустым**.
4. Нажать «Показать результат». Отчёт указывает доставленные VIN-ответы, пробные запросы и наличие записанной CAN-трассы, **не выдаёт лабораторный ответ за подтверждённый OEM-модуль**.
5. Сохранить `%TEMP%\SectorVVirtualCar.log`. Для дальнейшего оживления сети нужны **реальные CAN-логи** конкретных диагностических ответов CEM и ECM/TCM, особенно `B9 F0`. Без них новые узлы остаются честно выключенными.

Полный VIN и содержимое EEPROM не публикуйте. Диагностический лог может содержать VIN в hex.

## 4. Проверки

- Сверены пять M32C-дампов CEM: строки HW-кандидатов и указатели F0 без декодирования EEPROM.
- Сборка DLL и GUI PE32 x86; Go unit tests и `go vet`.
- C host-тесты, включая ASan/UBSan: D2 сети с отдельным Target, правильная скорость 125/500, одиночные и многокадровые ответы, защита от подмены.
- Опциональный пассивный CAN в обеих скоростях, без фоновых поддельных кадров по умолчанию.
- Регрессии J2534, ISO15765 RxStart и OBD VIN.
- Unit-тесты сканера Flash, в отчёте нет полного VIN.
- Целостность архивов и отдельная проверка публичного ZIP на личный VIN.

Офлайн проверки не заменяют тест VDASH на Windows. Никакого утверждения об успешном обнаружении остальных ECU в этом выпуске нет.
