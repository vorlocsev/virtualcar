# SectorV Virtual Car 0.3.4: проверка полноты P2 D2 и согласованности VIN

5. Исправлена подпись `FF C8` в сводке: это команда сброса, а не доказанный запрос обнаружения автомобиля.
6. Реальный VIN владельца в публичные ZIP **не включается**; личный профиль устанавливается отдельным приватным архивом.

# SectorV Virtual Car 0.3.3: анализ реального P2 CAN-LS/CAN-HS

Эта версия **не изменяет** 13-кадровый ответ `B9FB` и не добавляет неподтверждённые байты CEM. Установленная DLL по-прежнему работает только в изолированной виртуальной машине/ПК и не подключается к реальному CAN.

## Почему изменился вывод по обнаружению

В опубликованных P2 сеансах сначала идёт поиск CEM `0x40` на **CAN-LS 125 кбит/с**, затем чтение CEM `0x50` на **CAN-HS 500 кбит/с**. Неответивший `0x40` в таком сценарии **не доказывает неисправность**. См. https://www.matthewsvolvosite.com/forums/viewtopic.php?p=573011 и https://www.matthewsvolvosite.com/forums/viewtopic.php?p=601189

В опубликованных P2 логах `FF C8` используется при сбросе всех ECU после диагностической процедуры. Ранее мы неверно называли её `discovery probe`. Теперь DLL регистрирует `P2 FF C8 broadcast reset: no physical ECU; intentionally silent`. Поскольку физического ECU нет, никакой ответ не подделывается. См. https://www.matthewsvolvosite.com/forums/viewtopic.php?p=576761

## Изменения 0.3.3

1. При запросах `CB 40/50 B9 F0/FB` DLL фиксирует **target, opcode, baud, flags** для точного определения диагностической сети.
2. Кнопка **16. Аудит P2** показывает число запросов `B9FB` отдельно на CAN-LS 125 и CAN-HS 500 кбит/с.
3. Старые логи 0.3.1–0.3.2 обрабатываются по последней записи `PassThruConnect`. Это эвристика, при параллельных J2534 каналах возможны ошибки привязки.
4. `FF C8` считается по запросам приложения, а не по повторённым строкам комментария DLL. В отчёте это **запрос сброса**, а не незавершённое обнаружение.
5. `PassThruReadVersion` возвращает `VirtualCar-0.3.3`, интерфейс сообщает версию 0.3.3.

## Проверка

1. Полностью закрыть SectorV, VDASH, VirtualCarControl.
2. Распаковать пакет и переустановить J2534 через кнопку **1**, поскольку путь в реестре 32-bit должен указывать на новую DLL.
3. Выбрать **15. P2 B9FB (тест VIN)**. Затем **9. Начать новую сессию**.
4. Запустить SectorV в режиме P2, повторить определение автомобиля и нажать **16. Аудит P2**.
5. Проверить отображение CAN-LS / CAN-HS и число кадров от CEM `0x50`.

**Ограничение:** полученные SectorV 13 кадров не подтверждают VIN. Текущий синтетический VIN не связан с остальными полями исторической `B9FB`-записи, а OEM-проверки содержимого и контрольных сумм не верифицированы. Отсутствует достоверный полный набор данных для создания виртуального P2 XC90. Не использовать команды PIN, программирование, изменение конфигурации или сброс реальных ECU.

## Локальные проверки

- 11 Go-тестов P2-аудита.
- 6 Python-тестов импортёра.

# SectorV Virtual Car 0.2.10: исправление метаданных SAE J2534

**Причина обновления:** в v0.2.9 VDASH реально получал синтетические CAN-кадры, `START_OF_MESSAGE` и ответ `09 02`, но повторял обнаружение. Аудит исходников обнаружил нарушение формата возвращаемого `PASSTHRU_MSG`.

Исправления:

- Для **обычных RX-сообщений** поле `ExtraDataIndex` теперь равно `DataSize` (дополнительных байтов нет); ранее было `0`. Это стандартное требование J2534 v04.04.
- Для **индикации** `START_OF_MESSAGE` поле `ExtraDataIndex` остаётся нулевым, а длина равна четырём байтам CAN ID.
- `Timestamp` теперь возвращается в **микросекундах**, ранее из `GetTickCount()` поступали миллисекунды. 32-битное переполнение допустимо.
- В журнал ISO15765 добавлены `ExtraDataIndex` и `Timestamp` с указанием единиц.
- Добавлены отдельные локальные проверки всех этих полей. VIN, содержимое CEM и обработка защищённых запросов **не изменены**.

**Что нельзя утверждать:** наличие этих ошибок не доказывает, что VDASH именно из-за них не определял автомобиль. Нужна проверка на Windows.

## Проверка VDASH (A/B)

1. Закройте VDASH, VirtualCarControl и SectorV.
2. Распакуйте обновление в новую постоянную папку. Запустите VirtualCarControl от администратора и зарегистрируйте DLL заново.
3. Выберите **12. VDASH LAB (CAN + RxStart)**, запустите VDASH, проверьте обнаружение в течение одной короткой попытки.
4. Проверьте журнал `%TEMP%\SectorVVirtualCar.log`. Для полного ответа VIN `DataSize` и `ExtraDataIndex` должны быть `0x18` (24), для уведомления `START_OF_MESSAGE` значения должны быть `4` и `0`.
5. Если VDASH по-прежнему повторяет обнаружение, не меняйте VIN на реальный и не запускайте программирование. Требуется анализ ожиданий идентификации VDASH и тест с настоящим автомобилем или разрешённой диагностической трассой без секретных данных.

Программа остаётся **изолированным лабораторным эмулятором**. Тестовый VIN синтетический, а надёжная имитация Volvo CEM, PIN, лицензии и серверных модулей не реализованы.

# SectorV Virtual Car 0.2.9: диагностический профиль VDASH

**Что подтверждено:** VDASH (`vdash_u.exe`) открыл нашу J2534 DLL, измерил виртуальные 12,5 В, прослушивал CAN с таймаутом 100 мс, затем отправил `0x7DF: 09 02` и получил пакет VIN `0x7E8: 49 02 01 ...`. После этого повторял обнаружение. Доставка ответа **не доказывает**, что VDASH принял автомобиль.

Исправления v0.2.9:

- Ранее `PassThruStartMsgFilter` только логировал маску. Теперь установленные PASS/BLOCK/FLOW_CONTROL фильтры действительно применяются к входящим CAN ID. На канале без фильтров оставлена совместимость со старой самопроверкой.
- В ISO15765 убран лишний ответ VIN от CEM `0x72E` на функциональный OBD-запрос `09 02`: отвечает только ECM `0x7E8`.
- `PassThruReadMsgs` дополнительно логирует `ProtocolID`, `RxStatus`, `DataSize` для ISO15765.
- **Необязательный** сигнал `START_OF_MESSAGE` для составных ISO15765 сообщений. Управляется `EmitIsoRxStart=1` (по умолчанию отключён из соображений совместимости с предыдущими версиями).
- **Необязательная** синтетическая CAN-активность (ID `0x555`, ASCII `VCARLAB`), только на пассивном CAN-канале. Настройка `PassiveCAN.Enabled=1`; по умолчанию **выключено**. Это тест наличия входящих кадров, а не достоверная имитация зажигания Volvo.
- `virtualcar-vdash-lab.ini`: готовый тестовый профиль с обоими экспериментальными флагами для сравнения поведения VDASH.

## Сценарий A/B

1. Закройте VDASH, SectorV и VirtualCarControl.
2. Установите VirtualCar 0.2.9 в постоянную папку и зарегистрируйте адаптер (если папка новая).
3. **A:** нажмите **11. Базовый профиль**, затем запустите VDASH, сделайте короткую попытку подключения и сохраните журнал.
4. **B:** закройте VDASH, нажмите **12. VDASH LAB (CAN + RxStart)**, полностью перезапустите VDASH и повторите попытку. В журнале ожидается `Passive CAN lab traffic tick` и `RX START_OF_MESSAGE (ISO15765)`.
5. Сравните, меняется ли число циклов обнаружения и выдаёт ли VDASH VIN или другую ошибку. Если результата нет, закройте VDASH и восстановите кнопкой **11. Базовый профиль**. Базовый профиль также доступен как `virtualcar-default.ini`.

Не активируйте программирование, PIN decode, reboot, configuration write и облачные действия VDASH. Тестовые VIN/CAN данные не должны рассматриваться как реальные идентификаторы автомобиля.

# SectorV Virtual Car 0.2.8 (переключение лабораторных профилей)

Небольшой **лабораторный эмулятор** для проверки приложений, использующих интерфейс J2534 v04.04 (Windows x86). Он объявляет себя J2534-адаптером и эмулирует тестовые ECU (ECM и CEM) с синтетическим VIN. USB, CAN-адаптер и физический автомобиль не требуются.

**Важно:** совместимость с SectorV не подтверждена. Без изучения реальных вызовов SectorV нельзя утверждать, что он увидит автомобиль или загрузит внешние модули. Программа не изменяет SectorV.exe, не подменяет лицензии/авторизацию и не обращается к серверам.

## Запуск

1. Распакуйте архив в отдельную папку. Не помещайте DLL в каталог SectorV и не заменяйте его файлы.
2. Запустите `VirtualCarControl.exe` **от имени администратора** и нажмите `1. Установить адаптер`.
3. Нажмите `2. Проверить эмулятор`. В случае успеха появится тестовый VIN `YV1CZ0002A0000001`.
4. Закройте и заново откройте SectorV, попробуйте выбрать **SectorV Virtual Car (J2534)** вместо DiCE/Mongoose, если в SectorV вообще есть выбор стандартного J2534-интерфейса.
5. Нажмите `5. Проверка CEM P3 / D2`, чтобы проверить ответы лабораторного CEM. Это не подтверждает совместимость с SectorV.
6. Откройте `4. Журнал обмена`. Запросы из SectorV записываются в `%TEMP%\SectorVVirtualCar.log`.
7. Чтобы удалить виртуальный адаптер, нажмите `6. Удалить адаптер` от имени администратора. Другие драйверы/записи J2534 не меняются.

Альтернатива графическому установщику: запустите PowerShell **от имени администратора**, перейдите в папку архива и выполните `& .\scripts\install.ps1`. Для удаления выполните `& .\scripts\uninstall.ps1`.

## Что поддерживается

- Экспорт SAE J2534 v04.04: Open/Close, Connect/Disconnect, ReadMsgs/WriteMsgs, MsgFilter, ReadVersion, Ioctl и остальные базовые функции.
- CAN (5), ISO15765 (6), адаптер регистрируется в **32-битном представлении** `HKLM\SOFTWARE\PassThruSupport.04.04`.
- UDS `10` (session control), `22 F190` (VIN), `22 F114` (P3 CEM VIN, экспериментальный ответ), `22 F187` (part number), `22 F189` (SW ID), `3E` (tester present).
- OBD `09 02` (VIN), данные синтетические.
- В CAN-режиме ответы длиной >7 байт выдаются через ISO-TP First Frame и Consecutive Frame после Flow Control. В ISO15765-режиме транспортная упаковка скрыта от приложения.
- Команды SecurityAccess (`27`), WriteDataByIdentifier (`2E`), RoutineControl (`31`), RequestDownload (`34`), TransferData (`36`) и сбросы отклоняются. Никаких изменений реального ECU нет.
- Настраиваемый профиль `virtualcar.ini`: тестовый VIN, имитация напряжения, до 8 пар CAN request/response ID.

## Известные ограничения

- Требуется **32-битное приложение** или клиент, способный загрузить 32-битный J2534 DLL. Для x64 нужна отдельная сборка.
- J2534 **v05.00**, собственный протокол DiCE, аппаратный USB-поиск и нестандартные интерфейсы SectorV не эмулируются.
- Нет настоящего CAN, K-line, полного ISO-TP приёма длинных запросов, реальных CEM/ECM идентификаторов, PIN, серверных модулей и механизма лицензирования.
- `StartMsgFilter` принимает любой ответ и пока не фильтрует сообщения по маске; `StartPeriodicMsg` имитирует одну отправку, а не периодическую передачу.
- Самопроверка DLL и локальные протокольные тесты **не являются** тестами совместимости с SectorV. GUI/библиотека пока не исполнялись на реальной Windows в данной среде.

## Новое в v0.2: диагностика запроса SectorV

Журнал пользователя показал попытки P3 CEM `0x726: 03 22 F1 14` и D2 `0x000FFFFE: CB 40 B9 FB` / `CB 50 B9 FB`.

- Добавлен второй синтетический ECU с ID `726/72E`: в версии 0.2.3 запрос `22 F1 14` получает положительный UDS-ответ `62 F1 14` с 17 ASCII-символами тестового VIN. Формат полезных данных является лабораторным допущением, а не подтверждённой записью реального ECU.
- Для D2 `B9 FB` добавлено обнаружение запросов на адреса `40` и `50`. **Реальный блок Vehicle Information не подделывается**: формат и контрольные суммы зависят от ECU. Без проверенной тестовой последовательности ответ не генерируется.
- Можно задать последовательность из 1..16 кадров D2 CAN в секциях `[D2_40]` / `[D2_50]`, например:

```ini
[D2_40]
ResponseId=00800003
B9FBFrameCount=1
B9FBFrame0=CC 40 7F B9 31 00 00 00
```

Пример выше выдаёт **отрицательный** ответ только для проверки прохождения кадров и не является данными реального автомобиля. Для положительных ответов используйте только собственные проверенные лабораторные фикстуры с несекретными данными. Приём и регистрация ответов по J2534 не доказывают, что SectorV загрузит серверные модули.

- Лог `PassThruConnect` теперь содержит `protocol / flags / baud` (три 32-битных числа в big-endian).
- `PassThruStartMsgFilter` показывает маски, шаблоны и FlowControl, но фактическое применение фильтров остаётся ограничением текущей версии.
- Сообщения с 29-битными ID помечаются битом `CAN_29BIT_ID` в `RxStatus`.
- `PassThruReadMsgs` использует `ERR_TIMEOUT` при ненулевом таймауте и `ERR_BUFFER_EMPTY` при нулевом.

Обновление DLL: полностью закройте SectorV, затем замените DLL и INI или распакуйте v0.2 в новую папку и повторно зарегистрируйте адаптер.

- D2 `B9 FB` на адресах 0x40/0x50 **не изменён**: без корректного ответа Vehicle Information этот путь пока не даёт VIN. Не рассчитывайте на распознавание P2.

**Инструкция обновления:** полностью закройте SectorV и эмулятор. Распакуйте **в отдельную постоянную папку**, запустите `VirtualCarControl.exe` как администратор и снова нажмите `1. Запустите `2. Проверить эмулятор`, затем `5. Проверка CEM P3 / D2`. В обоих случаях должен появиться **один и тот же** тестовый VIN из `virtualcar.ini`. ## v0.2.4: анализ пользовательского журнала и необязательные DID-ответы

Из журнала v0.2.3 видно, что настоящий SectorV отправил `22 F114` на `0x726`,
получил VIN в трёх ISO-TP кадрах, затем попытался прочитать `22 F1B0`

в OEM-протоколе **не подтверждена**. Мы не заявляем совместимость с SectorV.

Изменения:

- В INI профиля каждого ECU можно прописать `DIDF1B0Hex` и `DIDF1A3Hex`.

- `0x000FFFFE: FF C8` отдельно журналируется как D2 discovery probe,
  но ответ не генерируется без верифицированного формата.
- Исправлено противоречие, когда успешно обработанные широковещательные
