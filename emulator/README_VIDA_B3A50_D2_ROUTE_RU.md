# B3A50: классификация реальных запросов D2 в сохранённом окне VIDA

**Цель:** объяснить 3 `strict_bus_rejected` и 3 `no_validated_fixture` из
операторского B3A49. Не делать новую попытку `READ VEHICLE`.

Исходники лабораторной x86 DLL PR #319 показывают, что маркер
`P2 D2 request target/opcode/baud/flags (BE)` содержит ровно четыре
32-битных слова Big Endian. Внутри того же процесса логируются метки
исхода `strict route rejected`, `no validated response fixture`,
`no target fixture`, `recorded frames staged`, последние с 4 байтами
`CB <target> B9 <opcode>`.

Инструмент `emulator/tools/audit_vida_b3a50_d2_matrix.py` предоставляет
чистую функцию `analyze(lines)`. Она **не открывает ни одного исходного
журнала** и принимает только уже проверенный срез (например, замороженное
append-окно B3A47). Результат только категориальный: `CEM_40/CEM_50`,
`B9FB/B9F0/B9FC`, известные скорости, число запросов и категорию исхода.
Сопоставление основано на текстовой метке того же процесса и расстоянии
не более 24 строк. Перекрывающиеся или неизвестные соответствия
обозначаются отдельно; подстановка соответствий запрещена.

Для ранее сохранённого частного запуска владельца подготовлен независимый
локальный `Invoke-VirtualCar-B3A50-D2RouteMatrix.py`, который сверяет
старую B3A47 baseline SHA-256 и строго ограниченный размер исходного
окна, используя проверенный B3A49 локальный helper. Оба инструмента
работают только на чтение. Никакие оригинальные записи и VIN не обезличиваются
или переписываются на машине владельца, но публичный вывод **не содержит**
сырых логов, PID, путей, CAN, VIN или неизвестных значений метаданных.

**Важно:** `CEM_40` и `CEM_50` лишь цели запроса, а не проверенный
источник MY2009. Исходные настройки базового эмулятора для них
125/500 кбит/с являются **гипотезой конфигурации**, не схемой OEM.
В PR #319 возможны дополнительные фикстуры со своими скоростями,
поэтому `differs_from_base_fixture_baud` не удостоверяет причину
отказа. Даже `recorded_frames_staged` не является доставленным
ответом ECU. `same_logger_prefix` не подтверждает подлинность
оригинального процесса VIDA.

Ни каналы J2534, ни INI, ни OEM фикстуры, ни GUI VIDA, ни `main`
и публикации данным этапом не меняются. Для положительного VIN
необходим отдельно доказанный RX и принятие в оригинальном VIDA GUI.

Связано с Issue #326 и #4; оба остаются OPEN.
