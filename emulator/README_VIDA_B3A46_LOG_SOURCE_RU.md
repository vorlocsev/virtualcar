# B3A46: определение журнала виртуального J2534

Лабораторные вызовы B3A7 **не доказывают** выполнение оригинальной VIDA ReadVin. Для инструмента B3A45 нужен точный путь к `SectorVVirtualCar.log`. Исходники PR #319 показывают вызов `GetTempPathA` **из контекста процесса-клиента**. Поэтому `$env:TEMP` в отдельном PowerShell может отличаться от TEMP у VIDA.

## Ограниченный поиск, только чтение

Инструмент `emulator/tools/audit_vida_b3a46_log_source.py` проверяет **только один файл с точным именем** непосредственно в известных временных каталогах. Рекурсивного сканирования нет. Дополнительные каталоги задаются исключительно через `--root`. Хвост до 64 КиБ читается локально для подсчёта известных маркеров, но сырые строки, VIN, CAN, PID и пути не выводятся на экран.

Команда в той же гостевой Windows, где установлена оригинальная VIDA:

~~~powershell
$private = Join-Path $env:LOCALAPPDATA 'VirtualCar\OwnerPrivate\B3A46'
py -3 emulator\tools\audit_vida_b3a46_log_source.py --private-manifest (Join-Path $private 'candidate-paths.private.json')
~~~

Проверяются `TEMP`, `TMP`, `LOCALAPPDATA\Temp`, `WINDIR\Temp` и TEMP системного профиля Windows. Путь к дополнительному каталогу можно явно передать через `--root <каталог>`. Этот путь не публикуйте. **Приватный manifest содержит пути**, остаётся только у владельца и не загружается в GitHub.

Результаты:
- `ONE_PLAUSIBLE_SOURCE`: только один кандидат с маркерами VirtualCar в последних 64 КиБ;
- `MULTIPLE_PLAUSIBLE_SOURCES`: требуется локально выбрать источник;
- `NO_BOUNDED_MATCH`: явные каталоги не дали совпадений, но журнал может находиться в ином TEMP или нужные маркеры лежать раньше хвоста.

Это *кандидаты на файл*, не доказательство, что оригинальная VIDA выбрала или загрузила DLL. После ручной проверки пути в приватном manifest используйте его как `--virtual-log` для B3A45, создайте **новый** baseline и только затем проводите одну добровольную read-only проверку в виртуальной машине без физического DiCE/J2534 и автомобиля. Не выполняйте SecurityAccess, программирование или изменение конфигурации.

Локальный K-Line ACK, отладочный TX и синтетический RX не являются подтверждением ответа ECU. **Оригинальная VIDA ReadVin, реальный CEM RX и принятие VIN остаются NOT_VERIFIED**, пока отсутствуют независимые результаты клиентской сессии. См. Issues #4 и #326.
