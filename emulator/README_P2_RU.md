# SectorV Virtual Car 0.3.4: проверка полноты P2 D2 и согласованности VIN

**Цель:** диагностировать именно то, что SectorV получил в `B9 FB` от CEM `0x50`, без создания непроверенных ответов и без утверждений об успешной идентификации автомобиля.

## Отличия от 0.3.3

1. **Кнопка 16 / Аудит P2** анализирует каждую отдельную попытку `CB 50 B9 FB`: принимает только реальные строки `PassThruReadMsgs -> delivered`, проверяет заголовок `8F 50 F9 FB`, номера `09–0F, 08–0B` и завершение `4F`. Простой счётчик `13` больше не означает корректный ответ.
2. По каждой попытке выводятся количество доставленных кадров, полнота, нарушения последовательности. Анализ по-прежнему **не означает**, что SectorV принял VIN.
3. Добавлена необязательная строка `ModelYear` в `[Vehicle]`. Аудит сверяет десятый знак VIN с указанным годом без североамериканской проверки контрольной цифры (для европейского XC90 она неприменима как обязательное правило).
4. В экспериментальном P2-профиле добавлено `FixtureProvenance = historical_public_2005_fixture_with_replaced_VIN`. В отчёте предупреждение: фрагмент `200512` присутствует в исходной записи, но его назначение **не расшифровано**. Нельзя считать остальные поля принадлежащими автомобилю, VIN которого подставлен.
5. Исправлена подпись `FF C8` в сводке: это команда сброса, а не доказанный запрос обнаружения автомобиля.
6. Реальный VIN владельца в публичные ZIP **не включается**; личный профиль устанавливается отдельным приватным архивом.

**Важно для Windows:** после распаковки в новую папку повторно зарегистрируй J2534 адаптер кнопкой 1. Установи личный профиль из отдельного архива только после распаковки приложения. Запусти SectorV → P2, затем нажми 9 перед новым сеансом и 16 для аудита. **Кнопка 15 необязательна**: приватный установщик уже обновляет `virtualcar.ini` и исходный файл профиля. Не применяй «Базовый профиль» (кнопка 11), иначе приватный вариант будет сброшен.

**Проверка на Windows:** до пользовательского запуска 0.3.4 не подтверждена. Локальные сборочные и протокольные тесты выполняются на Linux.

# SectorV Virtual Car 0.3.3: анализ реального P2 CAN-LS/CAN-HS

Эта версия **не изменяет** 13-кадровый ответ `B9FB` и не добавляет неподтверждённые байты CEM. Установленная DLL по-прежнему работает только в изолированной виртуальной машине/ПК и не подключается к реальному CAN.

## Почему изменился вывод по обнаружению

В опубликованных P2 сеансах сначала идёт поиск CEM `0x40` на **CAN-LS 125 кбит/с**, затем чтение CEM `0x50` на **CAN-HS 500 кбит/с**. Неответивший `0x40` в таком сценарии **не доказывает неисправность**. См. https://www.matthewsvolvosite.com/forums/viewtopic.php?p=573011 и https://www.matthewsvolvosite.com/forums/viewtopic.php?p=601189

В опубликованных P2 логах `FF C8` используется при сбросе всех ECU после диагностической процедуры. Ранее мы неверно называли её `discovery probe`. Теперь DLL регистрирует `P2 FF C8 broadcast reset: no physical ECU; intentionally silent`. Поскольку физического ECU нет, никакой ответ не подделывается. См. https://www.matthewsvolvosite.com/forums/viewtopic.php?p=576761

## Изменения 0.3.3

1. При запросах `CB 40/50 B9 F0/FB` DLL фиксирует **target, opcode, baud, flags** для точного определения диагностической сети.
2. Кнопка **16. Аудит P2** показывает число запросов `B9FB` отдельно на CAN-LS 125 и CAN-HS 500 кбит/с.
3. Старые логи 0.3.1–0.3.2 обрабатываются по последней записи `PassThruConnect`. Это эвристика, при параллельных J2534 каналах возможны ошибки привязки.
4. `FF C8` считается по запросам приложения, а не по повторённым строкам комментария DLL. В отчёте это **запрос сброса**, а не незавершённое обнаружение.
5. `PassThruReadVersion` возвращает `VirtualCar-0.3.3`, интерфейс сообщает версию 0.3.3.

## Проверка

1. Полностью закрыть SectorV, VDASH, VirtualCarControl.
2. Распаковать пакет и переустановить J2534 через кнопку **1**, поскольку путь в реестре 32-bit должен указывать на новую DLL.
3. Выбрать **15. P2 B9FB (тест VIN)**. Затем **9. Начать новую сессию**.
4. Запустить SectorV в режиме P2, повторить определение автомобиля и нажать **16. Аудит P2**.
5. Проверить отображение CAN-LS / CAN-HS и число кадров от CEM `0x50`.

**Ограничение:** полученные SectorV 13 кадров не подтверждают VIN. Текущий синтетический VIN не связан с остальными полями исторической `B9FB`-записи, а OEM-проверки содержимого и контрольных сумм не верифицированы. Отсутствует достоверный полный набор данных для создания виртуального P2 XC90. Не использовать команды PIN, программирование, изменение конфигурации или сброс реальных ECU.

## Локальные проверки

- 11 Go-тестов P2-аудита.
- 6 Python-тестов импортёра.
- C-тест виртуальной DLL (P2 B9FB 13 кадров, B9F0, P3, ISO-TP, отказ от программирования).
- Компиляция DLL и GUI PE32 для Windows x86, проверка J2534 экспортов.
- Запуск 0.3.3 непосредственно в SectorV/VDASH на Windows ещё **не выполнялся**.

# SectorV Virtual Car 0.3.2: аудит конфигурации Volvo P2

**Новый диагностический этап:** кнопка **16. Аудит P2** выполняет проверку текущего `virtualcar.ini` и журнала SectorV. Она не выполняет вызовов J2534, не отправляет диагностических команд и не изменяет данные автомобиля.

Проверка профиля:
- отдельно показывает записи для CEM `0x40` и CEM `0x50`, включая `B9F0` и `B9FB`;
- проверяет заголовок, последовательность и завершающий кадр D2 (не OEM-контрольные суммы);
- извлекает VIN из `B9FB`, сверяет его с `[Vehicle] VIN` и предупреждает о расхождении, **не печатая полный VIN**;
- показывает статус отсутствующих записей. Никаких неподтверждённых ответов для CEM `0x40` не добавлено.

Проверка журнала:
- после нажатия **9. Начать новую сессию** анализирует только новую сессию;
- если метка сессии отсутствует, берёт только последние записи **одного PID SectorV.exe**, а не смешивает разные версии и процессы;
- считает запросы `CB 40 B9 FB`, `CB 50 B9 FB`, количество доставленных кадров `0x01200003` и пробы `FF C8`;
- сохраняет полный текст отчёта в `%TEMP%\SectorVVirtualCar-P2-audit.txt`.

**Границы достоверности:** VIN может совпадать, но остальные исторические поля 2005-й записи остаются не согласованы с синтетическим автомобилем. Доставка всех 13 кадров не означает признание автомобиля SectorV. При отсутствии реального эталона ответа на `CB 40 B9 FB` эмулятор по-прежнему намеренно молчит.

**Проверка:** откройте VirtualCarControl 0.3.2, установите профиль кнопкой **15**, нажмите **9**, повторите подключение в SectorV и нажмите **16**. Также доступна кнопка **8** для общего отчёта.

# SectorV Virtual Car 0.3.1: Volvo P2, Vehicle Information B9FB

**Добавлено в 0.3.1:** демонстрация полного 13-кадрового ответа Volvo D2 `CB 50 B9 FB` с CAN ID ответа `01200003`. Основа: опубликованная read-only трасса DiCE: https://www.matthewsvolvosite.com/forums/viewtopic.php?p=573059 . Исходный VIN владельца **не включён** ни в исходники, ни в пакет; он заменён на синтетический VIN `YV1CZ0002A0000001`. Остальные поля исходного исторического Vehicle Information не были реконструированы для этого VIN, поэтому **полная идентификация автомобиля не гарантируется**. Эмулятор не подключается к физическому автомобилю.

## Быстрый тест SectorV (только P2)

1. Закрыть SectorV и VDASH. Распаковать ZIP в отдельный каталог. При смене каталога установить адаптер заново через кнопку **1** в `VirtualCarControl.exe` (с правами администратора).
2. Нажать **15. P2 B9FB (тест VIN)**. Создаётся резервная копия `virtualcar.ini`, устанавливается лабораторный профиль с 13 кадрами B9FB. Профиль остаётся в каталоге зарегистрированной DLL; переустановки после смены профиля не требуется.
3. Нажать **14. Проверка P2 D2**. Ожидаемый результат: `B9F0: 0 frames`, `B9FB: 13 frames`, ID `0x01200003`. Это тест транспорта, **не** подтверждение VIN в SectorV.
4. Нажать **9. Начать новую сессию**, запустить SectorV, выбрать J2534 Virtual Car и платформу **P2**, дождаться попытки обнаружения.
5. Нажать **8. Анализ журнала** и предоставить строки с PID `SectorV.exe`, включая `CB 50 B9 FB` и `PassThruReadMsgs -> delivered 01 20 00 03 ...`.
6. Для сравнения нажать **13. Volvo P2 (2005+)**: в этом профиле ответы B9FB отключены. После изменения профиля полностью закрыть и перезапустить SectorV.

**Безопасность:** используйте демонстрационный профиль только в изолированной среде и не включайте операции разблокировки, записи конфигураций, PIN, программирования или сброса ECU.

## Прилагаемые записи

- `samples/p2_b9f0_public_excerpt.txt` и `virtualcar-p2-historical-demo.ini` содержат старый трёхкадровый read-only пример `B9F0`.
- `samples/p2_b9fb_public_redacted.txt` содержит 13 кадров B9FB **с маскированным VIN (`XXXXXXXXXXXXXXXXX`)**.
- `virtualcar-p2-b9fb-demo.ini` содержит ту же 13-кадровую последовательность с маскированным VIN.
- `virtualcar-p2-b9fb-lab-vin.ini` содержит синтетический VIN для отдельной лабораторной попытки определения автомобиля. Файл переключается кнопкой **15**.

Оставшиеся исторические поля (номер детали, дата и т.д.) относятся к источнику, а не к синтетическому автомобилю. Не используйте эти данные как профиль настоящего XC90.

## Импорт собственной трассы DiCE/J2534

```powershell
python .\tools\import_p2_trace.py C:\Temp\my_dice_log.txt --target 50 --opcode FB --profile .\virtualcar-p2.ini --output .\my-p2-local.ini
```

Утилита выбирает только read-only запросы `CB 40/50 B9 F0/FB`, требует корректного первого кадра и последовательности D2, последнего кадра, одного CAN ID и максимум 16 кадров. VIN автоматически маскируется. При этом маскировка может нарушить OEM-контрольные суммы. Для локального эксперимента с синтетическим VIN можно добавить `--lab-vin YV1CZ0002A0000001`; **это не делает остальные поля соответствующими этому VIN**.

**Примечание:** P2 ранних лет, P1, P3, V8 и 3.2 с переходным типом CEM могут иметь другие ID или протоколы. Этот профиль основан на конкретной исторической трассе D2 и не считается универсальным. Для реального VIN необходим проверенный согласованный набор ответов именно нужного автомобиля. `FF C8` без проверенного ответа остаётся только в логировании.

## Пройденные локальные проверки

1. Импорт 13-кадровой исторической записи и автоматическая анонимизация VIN.
2. Проверка полей CAN ID, заголовка `8F 50 F9 FB` и конечного `4F`.
3. Отказ от усечённого и повреждённого D2-потока.
4. C-тест полного последовательного воспроизведения 13 кадров с таймингами.
5. Регрессия P3 VIN/ISO-TP, UDS, защиты от команд записи.
6. Windows x86 Clang/LLD: DLL, экспорт J2534; Go: GUI EXE.
7. Проверка состава/целостности архивов и отсутствия исходного VIN.

# SectorV Virtual Car 0.3.0: Volvo P2 (2005–2014), только чтение

**Результат:** отдельный P2-профиль, транспорт Volvo D2, поддержка реплея проверенных ответов CEM `B9 F0` (идентификация блока) и `B9 FB` (Vehicle Information), импорт текстовых журналов DiCE/J2534. Тесты сборки и протокола на Linux прошли. **VIDA, SectorV и VDASH не тестировались с этой версией на Windows.**

## Что известно из открытых источников

- Volvo P2 MY2005+ использует D2 over 29-bit CAN для части диагностики. В опубликованном сеансе DiCE запрос `000FFFFE: CB 50 B9 FB` получает ответ с 29-битным ID `01200003`, разделённый на несколько кадров: https://www.matthewsvolvosite.com/forums/viewtopic.php?p=573059
- В другой опубликованной трассе `CB 50 B9 F0` получает три кадра `01000003`, позволяющие прочитать номер CEM. Это исторический пример с конкретного автомобиля, **не профиль XC90 2007 V8**: https://www.matthewsvolvosite.com/forums/viewtopic.php?p=573057
- Для некоторых ранних P2 CAN-HS работает на 250 кбит/с, для MY2005+ на 500 кбит/с; низкоскоростная сеть может отличаться. Не объединяйте логи с разных годов/сетей: https://github.com/martonn98/VolvoP2_CAN

## Быстрая проверка P2 без автомобиля

1. Закройте SectorV и VDASH. Распакуйте приложение в постоянный каталог. Запустите `VirtualCarControl.exe` с правами администратора, установите адаптер кнопкой 1. При смене папки DLL зарегистрируйте адаптер заново.
2. Нажмите **13. Volvo P2 (2005+)**. Она сохраняет предыдущий `virtualcar.ini` в резервной копии и копирует `virtualcar-p2.ini`.
3. Нажмите **14. Проверка P2 D2**. В пустом профиле получите `B9F0: 0 frames` и `B9FB: 0 frames`. Это ожидаемо: реальная информация CEM НЕ генерируется из воздуха.
4. Для проверки только многокадрового воспроизведения `B9 F0` можно вручную скопировать `virtualcar-p2-historical-demo.ini` поверх `virtualcar.ini` (предварительно сохранив исходный файл). Это трёхкадровая запись исторического CEM с другого автомобиля, и она **не содержит VIN**. Перезапустите VirtualCarControl, проверьте кнопку 14, ожидаются **3 кадра B9F0, 0 кадров B9FB**.
5. Для проверки в SectorV: верните P2-профиль, нажмите 9 для новой сессии, запустите SectorV, выберите P2, затем нажмите 8 для анализа журнала. Ожидается `P2 D2 read command: no validated response fixture`, пока собственная проверенная запись `B9FB` отсутствует.

## Импорт собственных проверенных CAN-трасс

Дополнительная утилита `tools/import_p2_trace.py` требует Python 3 (сама DLL и EXE не требуют Python).

Пример импорта публичного **B9F0**-фрагмента, поставляемого в пакете без VIN:

```powershell
python .\tools\import_p2_trace.py .\samples\p2_b9f0_public_excerpt.txt --target 50 --opcode F0 --profile .\virtualcar-p2.ini --output .\virtualcar-p2-local.ini
```

Чтобы получить **B9FB**, нужен полный собственный или публичный подтверждённый read-only J2534/DiCE журнал от **согласованной модели и поколения**. Пример команды:

```powershell
python .\tools\import_p2_trace.py C:\Temp\my-own-dice-session.txt --target 50 --opcode FB --profile .\virtualcar-p2.ini --output .\virtualcar-p2-local.ini
```

Импортёр по умолчанию заменяет найденные последовательности, похожие на VIN, на `X`. Такая анонимизация может нарушить контрольные суммы и не годится для проверки полной идентификации. Для личной изолированной работы с трассой собственного автомобиля можно указать `--keep-identifiers`, при этом **не публикуйте полученный INI**. Не импортируйте фреймы доступа к PIN/иммобилайзеру, сессионные ключи или команды записи: программа поддерживает только `CB 40/50 B9 F0/FB`.

Импортёр не записывает настройки в запущенный SectorV и не меняет реальный автомобиль. Чтобы попробовать созданный файл, закройте SectorV, скопируйте сохранённый INI в `virtualcar.ini` рядом с **зарегистрированной** DLL, затем повторите подключение.

## Транспорт и конфигурация

В `virtualcar-p2.ini`:

- `ECUCount=1`: отключает эмуляцию P3 CEM `0x726`; базовый OBD ECM `0x7E0` оставлен для совместимости.
- `[P2] ReplaySpacingMs=12`: выдача каждого следующего D2-кадра с интервалом 12 мс. Ноль отключает задержку; значения более 250 мс ограничиваются.
- `[D2_50] ResponseId=01200003`: опубликованный ID для **конкретного** исторического `B9FB`-сеанса, не универсальное правило Volvo.
- `[D2_50_B9F0] ResponseId=01000003`: ID из отдельно опубликованного `B9F0`-сеанса.
- `[D2_40]` и `[D2_40_B9F0]`: альтернативный адрес CEM, ответы по умолчанию выключены.
- Для каждой записи задаются `B9FBFrameCount=N` и `B9FBFrame0..F` либо `FrameCount=N` и `Frame0..F`. Максимум 16 кадров. Каждое значение ровно 8 байт без 4-байтового CAN ID.

## Что *не* поддерживается

- Никакой настоящий VIN P2 не появляется из одной настройки `VIN=...`. Для P2 нужен согласованный ответ Vehicle Information `B9FB`.
- `FF C8` из лога SectorV по-прежнему фиксируется, но без подтверждённой пары ответа не обрабатывается.
- Генерация настоящего зажигания CEM, таблиц ECU, функций иммобилайзера, доступа к PIN, прошивки или изменения конфигурации запрещена в этой диагностической сборке.
- Это лабораторный инструмент без связи с физическим CAN; успешный ответ J2534 не равен принятию автомобиля SectorV или VDASH.

## Локальные проверки (8)

1. Host C-тест: регрессия P3 VIN и UDS.
2. Host C-тест: D2 `B9F0` с CAN ID `01000003` и тремя кадрами.
3. Host C-тест: D2 `B9FB` с CAN ID `01200003`, многокадровая передача и задержки.
4. Host C-тест: пустая запись D2 не подставляет выдуманные ответы.
5. Host C-тест: защищённые запросы UDS не разблокируются.
6. Python unit-тесты парсера: импорт/редакция VIN/исключение записи.
7. Cross-build: Windows PE32 EXE и DLL, функции J2534.
8. Целостность и состав ZIP пакетов.

*Реальные испытания на Windows и физических адаптерах ещё не проводились.*
