# Импорт D2: сохранность исходников и точное эхо ответа

`tools/import_p2_trace.py` по-прежнему импортирует только записанные
read-only B9F0/B9FB/B9FC, target 40/50. Фикстуры не создаются автоматически.
Этот этап не меняет DLL, маршруты, CAN payload или положительные CEM ответы.

Ранее `--output` открывался в режиме записи с перезаписью. Проверка
защищала исходный INI, но не входной лог, существующий выходной файл или
hardlink входного лога. На synthetic тестах воспроизведена потеря исходного
содержимого. Теперь output должен быть новым файлом: входной log/profile
отклоняется заранее, а эксклюзивное создание защищает остальные существующие
пути, включая hardlink/symlink и файл, появившийся после проверки пути.
Ошибки создания output завершаются кодом 2 с общей диагностикой без
подстановки частного пути. Для повторного импорта выберите новое имя.

Прежняя однокадровая проверка принимала корректные control/target без
проверки эхо сервиса. Поэтому ответ другой команды мог попасть в INI,
после чего DLL его отключала. Импортер теперь согласован с её проверкой:
положительное эхо F9 + запрошенный opcode либо записанный отрицательный
ответ 7F B9. Отрицательный ответ сохраняется без превращения в положительный;
это транспортная проверка, не подтверждение идентичности или OEM семантики.

Восемь новых групп проверяют: разрешённые target/opcode; отрицательное эхо;
чужое/произвольное эхо; сохранность входного лога; сохранность существующего
output; INI и hardlink; успешный новый импорт 13 кадров и редактирование
VIN на границе кадров; недопустимую фикстуру и ошибку создания файла.
Все данные тестов synthetic либо прежние обезличенные excerpts репозитория.
Локально прошли 14 тестов импортера, включая шесть существовавших.

Контекст Issue #4: native regression настоящей x86 DLL выполнена внутри
VMware. Отдельный read-only сеанс SectorV 1.1.0 подключил новую виртуальную
регистрацию и показал 12,5 В, но закончился «Не удалось получить VIN»:
13 запросов, 10 no_fixture B9FB, два unsupported P3 F114, один wrong-baud,
ноль RX/конфликтов. Частная существующая MY2005 фикстура отдельно доставлена
как 13 побайтно совпавших кадров через native READ128, без потерь и конфликтов.
Она не подтверждена для MY2009 и не включается в активный профиль или GitHub.
Исходный private INI и пользовательский backend в этом replay не менялись.

Следующий функциональный блокер — подлинная совместимая запись CEM для
целевого MY2009 с происхождением и маршрутом. Успех импорта или доставки
не доказывает принятие VIN клиентом. Main, Dvinholm и опубликованный
VMware prerelease этим этапом не затрагиваются.
