# Virtual Car VMware LAB: read-only CEM discovery

**Назначение:** лабораторная сборка Virtual Car Windows x86 для проверки диагностических запросов Volvo P2 XC90 V8 MY2009 через виртуальный J2534 в гостевой Windows VMware. Это **не** подтверждённая имитация автомобиля и **не** программный пакет для реального ECU. Исходный коммит указан в BUILDINFO.json.

## Что включено

- VirtualCarJ2534.dll: виртуальный J2534 PassThru 04.04, только x86 (для 32-битного диагностического процесса).
- VirtualCarControl.exe: программа управления Windows x86, без отдельной среды .NET.
- Активный virtualcar.ini на основе строго маршрутизируемого **синтетического P2 профиля**: ECM и вымышленный VIN, P2 CAN-LS 125 кбит/с и CAN-HS 500 кбит/с. Отсутствуют подтверждённые положительные ответы CEM A3/A6/B9F0/B9FB/B9FC. Они не генерируются автоматически.
- Перед упаковкой проверяются полные SHA256 **двух утверждённых исходных INI**, `virtualcar-p2.ini` и `virtualcar-default.ini`, включая комментарии и неактивные поля. Даже при `FrameCount=0` строка `Frame0` или личный комментарий мог бы попасть в архив. Теперь любое незарегистрированное изменение INI блокирует сборку; для корректной новой синтетической версии требуется отдельная проверка и явное обновление хеша в `package_vmware_lab.py`. Проверка относится к этим двум INI и не является доказательством отсутствия любых возможных секретов во всём исходном коде.
- Включена только мета-телеметрия секции Diagnostics: BackendTelemetryEnabled=1. VIN и CAN payload не записываются в backend JSONL.
- Скрипты регистрации и удаления J2534 из 32-битного раздела реестра, Python-анализаторы, SHA256SUMS.txt и BUILDINFO.json.
- **Полный набор для одного реального GUI-сеанса SectorV:** `tools/invoke_sectorv_operator.ps1` (упрощённый интерактивный помощник), `tools/audit_sectorv_operator_session.py` (двухэтапный `begin/finish`), `tools/audit_vmware_sectorv_process.ps1` (пассивный снимок DLL при открытом клиенте), связанные анализаторы и `README_SECTORV_FRESH_WINDOW_RU.md`. Все зависимости Python включены в ZIP, запуск из полного исходного дерева не требуется.

## Импорт исторических B9FB: исходная фикстура не считается OEM автоматически

Утилита исходного дерева `tools/import_p2_trace.py` (не является частью
скачиваемого VMware LAB ZIP) импортирует локальные D2-кадры для отдельных
read-only исследований. При нескольких ответах на один D2-запрос она **не**
выбирает самый длинный ответ автоматически. Необходимо сначала просмотреть
локальный источник и указать индекс от нуля, например
`--session-index 1`; неверный индекс или неопределённый выбор не создаёт INI.
При единственном ответе индекс можно опустить.

В новом INI перед секциями записываются только комментарии с индексом и
**ограниченной категорией происхождения**: `emulator_tagged_rx` при явно
симуляторном формате RX либо `unverified_trace_origin` в остальных случаях.
Отсутствие маркера симулятора **не подтверждает** источник реального ECU:
воспроизведённые записи могут иметь такой же текст. В обоих случаях
`replay_approved=false`. Индекс, CRLF-структура, форма VIN или корректный
13-кадровый транспорт сами по себе не подтверждают XC90 V8 MY2009.
Приватный выходной INI не отправлять в GitHub и не подменять им исходный LAB
профиль. Для положительной приёмки нужен независимый разрешённый OEM-захват
с доказанными маршрутом, годом и целостностью кадров.

## Установка в VMware

1. В гостевой Windows 10/11 распакуйте ZIP **целиком в новую постоянную папку** (например, C:\VirtualCarVMware). Не запускайте EXE прямо из ZIP и не смешивайте со старой DLL.
2. Закройте SectorV, VDASH и старый VirtualCarControl. Создайте snapshot VMware до изменения реестра, особенно если уже установлены другие J2534 адаптеры.
3. В PowerShell **от имени администратора**, находясь в папке распаковки, выполните:

    .\scripts\install.ps1

   Скрипт регистрирует только пункт "SectorV Virtual Car" в 32-битном разделе HKLM\SOFTWARE\PassThruSupport.04.04. Не удаляет другие адаптеры. Действующий ключ под тем же именем будет обновлён на путь к этой DLL. Если PowerShell блокирует запуск из-за политики, изучите содержимое скрипта и разрешите локальный запуск по правилам вашей VM.
4. Откройте VirtualCarControl.exe и проверьте регистрацию J2534. При переключении профиля через GUI он заменяет virtualcar.ini и может отключить телеметрию. Для этого теста **оставьте исходный P2 профиль**. Если меняли его, повторно включите BackendTelemetryEnabled=1 через GUI или INI, затем перезапустите диагностический клиент.
5. В диагностическом клиенте выберите **SectorV Virtual Car (J2534)** и выполните короткое обнаружение/чтение модулей P2. Не выполняйте чтение PIN, Security Access, программирование, изменение конфигурации, сброс блоков или запись параметров. Не подключайте виртуальный адаптер к физическому автомобилю.

**Если клиент 64-битный:** x86 DLL он загрузить не сможет. Требуется 32-битный диагностический процесс. Гостевая Windows при этом может быть x64.

## Реальная проверка GUI и сохранение доказательств

В последней локально сформированной LAB-сборке выполните
[двухэтапную инструкцию](README_SECTORV_FRESH_WINDOW_RU.md) **из корня
распакованного каталога**, где находятся папка `tools` и
`VirtualCarJ2534.dll`. Скрипты `begin` и `finish` запускаются из
одной изолированной гостевой Windows с Python 3.12. До запуска
клиента подготовьте приватный манифест, во время открытого SectorV
при необходимости сохраните обезличенный снимок модулей, затем
после закрытия клиента выберите шесть фактически наблюдавшихся
категорий интерфейса. Скрипт не открывает клиент сам и не подаёт
диагностические команды.

**CI-проверка и приватный лабораторный пакет:** Windows VMware workflow
собирает Win32 `VirtualCarControl.exe` и уже протестированную x86
`VirtualCarJ2534.dll`. Сначала создаётся и проверяется временный ZIP:
SHA256, PE32, совпадение с исходными файлами, безопасный синтетический
профиль и отсутствие признаков подтверждения OEM. Эта первая копия
по-прежнему удаляется.

Только после **всех** успешных проверок при доверенном push владельца в
`development` CI повторно собирает локальный LAB ZIP с проверенной DLL,
проверяет внешний `.sha256` и загружает два файла как **приватный артефакт
GitHub Actions** с хранением **3 дня**. Это не GitHub Release, не публикация
для всех и не доказательство работы с настоящим SectorV. При ошибках CI
архив не загружается, временные файлы удаляются с постоянного runner.

## Получение пакета после зелёного CI

1. Авторизуйтесь в GitHub с доступом к приватному репозиторию
   `vorlocsev/virtualcar`. Откройте Actions → **Virtual Car VMware
   development validation** → последний **успешный** запуск именно на
   актуальном коммите `development`.
2. Внизу страницы запуска в **Artifacts** скачайте
   `virtualcar-vmware-lab-<SHA>-attempt-<N>`. Внешний ZIP GitHub содержит
   исходный `VirtualCar-VMware-LAB-ci-<12 символов SHA>-Windows-x86.zip`
   и одноимённый `.zip.sha256`. Имя и количество файлов нужно сверить.
3. Перед копированием в VMware сверьте SHA256 исходного ZIP со значением
   из `.zip.sha256`. В Windows:
   `Get-FileHash -Algorithm SHA256 -LiteralPath .\VirtualCar-VMware-LAB-*.zip`
   (при использовании PowerShell подставьте фактический путь к одному ZIP).
4. Распакуйте **внутренний** LAB ZIP в новую папку гостевой Windows и
   следуйте разделам «Установка в VMware» и «Реальная проверка GUI».
   Физический J2534 отключён; только чтение. Передайте только проверенные
   вручную обезличенные `p0-window.redacted.json` и
   `p0-triage.redacted.json`, не приватный манифест и не CAN/VIN-логи.

Артефакт доступен только пользователям с разрешением на приватный репозиторий,
не появляется на странице Releases и исчезает по истечении срока хранения.
Если на запуске нет Artifacts, проверьте статус заключительного шага
`Upload short-lived private VMware LAB x86 artifact`: зелёный статус
тестов без этого шага ещё не означает наличие скачиваемого пакета.


`BUILDINFO.json` содержит флаг
`two_phase_operator_collector_included=true`, но сохраняет
`vmware_e2e_verified=false` и
`operator_gui_acceptance_verified=false`. Наличие в пакете DLL
и инструментов не является доказательством загрузки DLL клиентом
или принятия VIN. Приватный файл `p0-before.private.json`, сырые
логи и снимки с идентификаторами в репозиторий не отправляйте.

## Как получить обезличенный отчёт

События сохраняются **под учётной записью, загрузившей DLL**, в файле:

    %LOCALAPPDATA%\VirtualCar\dev47-backend.jsonl

Полностью закройте клиент, скопируйте JSONL в личный локальный каталог и создайте отчёт на гостевой Windows с Python 3 либо на собственной машине:

    py -3 .\tools\audit_backend_evidence.py "C:\private\dev47-backend.jsonl" --output "C:\private\backend-audit.json"
Для отдельной проверки **J2534-подключения**, включая варианты протоколов из статического анализа P3Tool, после теста в этой сборке также доступен безопасный агрегированный отчёт:

    py -3 .\tools\audit_j2534_connect.py "$env:TEMP\SectorVVirtualCar.log" --output "$env:USERPROFILE\Desktop\j2534-connect-audit.json"

Анализатор читает локальный текстовый журнал, **но выводит только категории и количества попыток Connect/SET_CONFIG**, без CAN-кадров, VIN, PID процесса или путей. Программа не добавляет поддержку нестандартных протоколов 0x8004, 0x8005 и 0x10000001 и не эмулирует физический LS-CAN. Подробности в `README_P3TOOL_J2534_PREFLIGHT_RU.md`. Команда действует только с DLL нового CI, более ранний prerelease не содержит соответствующей телеметрии.


Если отчёт уже существует, выберите новое имя: анализатор не перезаписывает файлы. Отчёт содержит матрицу coverage для D2 A3/A6/B9F0/B9FB/B9FC и P3 F114/F1B0/F1A3/F106/F190. Статусы unimplemented_probe, no_fixture и delivered различаются. Delivered означает только выдачу RX через J2534, а не успешную идентификацию ECU клиентом. Если запрос не наблюдался, это **не** отказ ECU.

**Не публикуйте** исходный текстовый лог SectorVVirtualCar.log из %TEMP%, дампы, профиль донора или отдельные ZIP с личным VIN: в них могут содержаться идентификаторы. Для дальнейшего анализа достаточно backend-audit.json. Проверяйте содержимое отчёта перед отправкой.

## Восстановление и границы

Для удаления регистрации запустите PowerShell от администратора:

    .\scripts\uninstall.ps1

Он удаляет только виртуальную запись "SectorV Virtual Car". Перед перемещением папки закройте диагностический клиент и перерегистрируйте DLL по новому пути.

Эта сборка проверена автоматическими тестами и архитектурой PE32 в CI, **но ещё не проверена в настоящей гостевой VMware**. Нет подтверждения, что SectorV/VDASH примет XC90 V8 MY2009, прочитает VIN из OEM CEM или обнаружит полную сеть ECU. Значения B9FB от исторического Volvo P2 2005 нельзя считать проверенными MY2009. Положительных A3/A6 без подлинного захвата нет. Встроенный синтетический VIN не является данными пользователя.

Проверьте SHA256SUMS.txt внутри архива, BUILDINFO.json и внешний ZIP-файл .sha256 перед установкой. Никакого запуска физического J2534 в CI не выполнялось.
