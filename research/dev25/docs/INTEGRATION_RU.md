# dev25: интеграция с существующей VirtualCarJ2534.dll

Это **готовый к компиляции C99 модуль наблюдения**, но не полный PassThru драйвер. Исходник работающей v0.3.6.6 `virtualcar.c` по-прежнему недоступен. Здесь НЕ выполняется замена DLL, не производятся ответы и не меняется J2534 API. Сохраняйте штатную обработку диагностических запросов и 13 фрагментов B9FB.

## Конфигурация XC90 V8 MY2009

`p2_vehicle_xc90_v8_my2009_config()` устанавливает HS=500000, LS=125000. Пассивные CAN-сигналы из `olegel/VolvoCan` **выключены по умолчанию**. Автор VolvoCan использовал XC90 с собственными CAN ID; `0x00617FF8` для целевой машины пока не подтверждён.

Чтобы разрешить интерпретацию на тестовой машине, нужно отдельно получить фактический ID CEM и включить опцию:

```c
p2_vehicle_config cfg = p2_vehicle_xc90_v8_my2009_config();
cfg.enable_community_ls_signals = true;
cfg.observed_cem_ls_can_id = 0x00617FF8u; /* ТОЛЬКО если ID проверен на целевой машине */
p2_vehicle core;
p2_vehicle_init(&core, &cfg);
```

## Точки вызова J2534

1. После успешного `PassThruConnect` сохраняйте `ChannelID`, фактическую скорость и тип протокола. Физическая среда HS/LS устанавливается при подключении, а не по CAN ID.
2. В обработчике `PassThruWriteMsgs`, после проверки `DataSize >= 4` и `DataSize <= sizeof(Data)`, вызовите `p2_vehicle_observe_passthru_tx()` **только для наблюдения**. Передайте `ProtocolID`, скорость связанного канала и флаг 29-bit ID из J2534 `TxFlags`.
3. **Всегда** продолжайте оригинальный `PassThruWriteMsgs`. Поля `decision`, `generated_reply_count`, `must_forward_unchanged` НЕ являются J2534 status-кодами и НЕ меняют передачу.
4. После успешного чтения через `PassThruReadMsgs` для пассивных LS-кадров вызывайте `p2_vehicle_observe_rx()` с **фактическим** `ChannelID`/скоростью, подтверждённым 29-bit форматом, `DataSize-4`, реальным CAN ID и timestamp. Не направляйте в него ISO15765 payload как обычный DLC=8 CAN-кадр, если адаптер не отдаёт сырой CAN.
5. Для диагностики `E3 02` есть счётчик кандидатов `p2_vehicle_note_d2_candidate_rx()`. Вызывайте его **только после извлечения D2-body**, не для фрагментов с `CF/CB` и без контекста. Даже в этом случае счётчик не означает подтверждённую сессию.
6. Защищайте `p2_vehicle` одним mutex либо работайте в едином RX-диспетчере: модуль не содержит внутренних блокировок. Передавайте возрастающий timestamp для отсечения устаревших LS-кадров. Канальные `generation` / повторные Connect ведите в существующем J2534 dispatcher.

Пример минимального использования на C99: `examples/observer_hook.c`.

## Что НЕ делает dev25

- Не отвечает на A3/B9F0/B9E0 и не подтверждает обычный режим без реальной трассы.
- Не отправляет фоновые CAN-пакеты и не открывает физический шлюз автомобиля.
- Не имитирует включённое диагностическое зажигание; `diagnostic_ignition=UNKNOWN` независимо от пассивного ключа.
- Не реализует PIN, security access, ECU programming, EEPROM или иммобилайзер.
- Не гарантирует соответствие CEM/SWM/CCM/REM ID другого XC90 данным автора VolvoCan.

## Известная граница

`p2_cem_router.c` из dev23 содержит проверку D2 route `0x50/500k` и `0x40/125k` как текущую гипотезу. Несоответствие лишь помечается и не прерывает J2534 обмен. Корректность отдельных D2 CEM route для реального XC90 V8 MY2009 ещё требует эталонного лога.

Внешний источник пассивных сигналов: https://github.com/olegel/VolvoCan/blob/master/VolvoCan/include/VolvoCan.h . Исходные файлы автора в этот архив не копировались; логика декодирования самостоятельно реализована на основе наблюдаемых битов. Оригинал опубликован под LGPL-2.1.
