# Virtual Car v0.3.6.7-dev23: P2 CEM read-only source module

Это **исходный модуль для будущей интеграции**, не новая VirtualCarJ2534.dll и не OneClick. Существующий B9FB остаётся без изменений.

## Что сделано

1. Пассивное распознавание запросов CEM по реальному D2 CAN ID 0x000FFFFE.
2. Разделение маршрутов 0x50/500k и 0x40/125k, отдельная пометка несовпадения скорости.
3. Точный шаблон `A3 02 03 A5 A5 00`, другие A3, B9E0, B9F0, B9FB, B9FC.
4. Осторожная маркировка `A6 1A 04 01` как кандидата Reference 6660.
5. Раздельные валидаторы двухкадрового B9F0 (по независимому исходнику) и SectorV F0 (15-байтовое тело).
6. Отсутствие синтеза E3/F0/зажигания и гарантированный режим `KEEP_EXISTING` для B9FB.
7. Готовый Windows x86 COFF объект `build/p2_cem_router_x86.obj` и статическая библиотека `.lib`.
8. Документированная точка подключения к `PassThruWriteMsgs` без изменения его существующего статуса.

## Тестирование

`tests/run_tests.sh` — GCC/Clang, а также Clang ASan+UBSan. По 12 независимых групп тестов на каждой конфигурации. Тесты запускаются с синтетическими данными; запуск этой сборки внутри Windows VM не утверждается.

## Что НЕ сделано

- Не изменён оригинальный `virtualcar.c`: этого исходника нет в доступных рабочих файлах.
- Не создана заменяющая работающую DLL. Бинарный ответ A3/E3 не придуман.
- Нет подтверждённого F0 конкретного автомобиля, как и подтверждения Ignition ON.
- Нет внедрения в SectorV.exe, доступа к пользовательским токенам или к реальной машине.

Смотрите `docs/INTEGRATION_VIRTUALCAR_RU.md` и `docs/RESEARCH_RU.md`.
