# B3A312 — два XC90 кандидата BaseData и их профили MY2009/B8444S

Дата: 2026-11-19. Draft PR #376. Только работа с локальной офлайн-копией владельца.

## Доказанное основание

Владелец подтвердил, что BaseData.VehicleModel содержит 45 строк, из которых
ровно **две** имеют название с отдельным токеном XC90 в начале,
без единого точного Description = XC90. Это не ошибка отсутствия модели:
прежняя проверка только точного совпадения вернула model=zero, year=one,
engine=one и counts=null.

Предшествующий приватный аудит шести внутренних FK связей успешно посчитал
BaseData.VehicleProfile=139578 строк и CarCom.T161_Profile=147647 строк,
без пропущенных и неоднозначных целей для заполненных ссылок.
Исходный набор 43 XC90 V8 MY2009 в CarCom **не восстановлен**.

## Новый инструмент

emulator/tools/audit_vida_basedata_xc90_candidates.py

Он открывает только E:\VirtualCar\VIDA-private\BaseData.sqlite,
в режиме mode=ro&immutable=1 + PRAGMA query_only=ON. Обязательная
проверка исходного экспортного каталога, обычных физических таблиц,
количества строк, отсутствия WAL/SHM/journal, ограничений времени и
размера данных выполняется до чтения.

В памяти ищет не более восьми VehicleModel, у которых
Description начинается с токена XC90, не принимая XC900.
Модельные ID, описания и прочие значения не покидают процесс.
Отдельно однозначно проверяет ModelYear.Description = 2009 и
Engine.Description = B8444S. Если год или двигатель неоднозначны,
список числовых профилей не строится.

Для каждого модели-кандидата считает только числовые классы по
BaseData.VehicleProfile: все годы, 2009 с любым двигателем,
2009/B8444S, 2009/NULL двигатель,
NULL год/B8444S и NULL год/NULL двигатель.

Кандидатские векторы сортируются **по числам**, а не по приватным
описаниям или ID. Позиция в JSON не является идентификатором модели
и не подходит для дальнейшей выборки через сохранённую нумерацию.
Классы могут пересекаться по условиям года/двигателя; векторная
проверка контролирует только непротиворечивые вложенные количества.

## Windows, команды из корня checkout PR #376

Сначала получить изменения:

    git pull --ff-only

Запустить новый синтетический набор (13 групп):

    py -3 -m unittest discover -s emulator/tests -p test_vida_basedata_xc90_candidates.py -v

При успешном OK — локальный агрегированный аудит:

    py -3 .\emulator\tools\audit_vida_basedata_xc90_candidates.py --folder 'E:\VirtualCar\VIDA-private'

Ни один источник не записывается. Выход — только JSON.
Данный инструмент не создаёт p0-exact-43-private.txt и
p0-general-private.txt и не выполняет JOIN BaseData ↔ CarCom.

Всегда false: model_identity_resolved,
cross_database_profile_mapping_verified,
original_selection_of_43_reconstructed,
actual_vida_vehicle_profile_selection_verified,
original_vida_readvin_accepted.

**Даже если один кандидат имеет ненулевое число 2009/B8444S, а другой ноль,
это ещё не доказательство выбранного профиля VIDA или исходных 43 CarCom
профилей**. Сначала потребуется доказательное сопоставление структур
двух баз, а затем независимо проверенный критерий исходной выборки.

Статус нового этапа на момент написания: 13 синтетических тестовых
методов добавлены; выполнение тестов и оригинального агрегата на
Windows владельца ещё не подтверждено. Original VIDA/SQL, main,
development, J2534, ECU и релизы не изменялись.
