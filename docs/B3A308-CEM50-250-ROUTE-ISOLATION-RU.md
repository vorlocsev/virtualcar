# B3A308 — отдельный маршрут CEM node 0x50 / CAN 250 kbit/s (Draft)

Дата: 2026-11-18. Основа: exact-head интеграционного Draft PR #352, `ac7e559e70dd3b76d82f5849fd59d0808d033e7b`.
Этот PR — **только предлагаемое изменение**, не выпуск и не VIDA ReadVin acceptance.

## Проверенная мотивация

Оригинальная VIDA 2014D в журнале `VIDA-KLine-B2-runtime-20261111-105658.txt`
последовательно попыталась прочитать VIN по:
1. GGD CEM config 611, ISO15765 / 500000, `0x726 22 F1 14`;
2. D2 CEM config 240, CAN_PS / 125000, `0xFFFFE CB 40 B9 FB ...`;
3. D2 **та же CEM variant 230** config 241, CAN / 250000, `0xFFFFE CB 50 B9 FB ...`;
4. D2 **другая PJB variant 70** config 74, CAN / 500000, `0xFFFFE CB 50 B9 FB ...`.

Все четыре попытки в **этом** журнале завершились тайм-аутом; достоверный OEM RX для CEM 50/250k в нём отсутствует.
Источниковедческий обзор — Draft PR #371, `docs/research/vida-b3a307-f114-b9fb-readvin-route-evidence-2026-11-18.md`.
Не следует утверждать, что один логический адрес 0x50 однозначно определяет ECU.

## Изменения B3A308

- В `emulator/src/virtualcar.c` выделен фиксированный индекс `CEM50_250_FIXTURE=15`, сохранены все старые индексы 0..14 (включая AE1B=14 и D2_Node0..7).
- Новый INI раздел `[D2_CEM50_250_B9FB]` **Enabled=0**, сеть: только обычный `PROTO_CAN` / 250000, target `0x50`, service `B9`, subcommand `FB`. При включении **ResponseId обязательно указывается самостоятельно**; выдуманный CAN ID не используется.
- При поиске target 0x50 скорость проверяется **вне зависимости от `P2.StrictRouting`**: legacy 500000 не может отвечать на 250000. При несовпадении скорости поиск продолжается к следующему слоту вместо преждевременного возврата.
- В защите дубликатов учитывается baud наряду с target/service/opcode. Два слота для 0x50/B9FB при 250000 и 500000 не конфликтуют.
- Диагностическая метка target 0x50/500000 теперь `ECU_OTHER` (не `CEM`), поскольку реальный XML относит этот запрос в исследованной ветке к PJB; это **не** доказательство PJB по любой трассе 500k.
- CEM 0x40/125000 CAN_PS доступен только через отдельный opt-in J2534-2 из основы PR #352. B3A308 не устанавливает драйвер и не изменяет его opt-in.
- `emulator/virtualcar-p2.ini`: добавлен пустой выключенный профиль, без VIN, ECU-данных и OEM фреймов.

## Восемь синтетических регрессий в host C

`emulator/tests/virtualcar_test.c` содержит `test_b3a308_cem50_250_route_isolation`:

1. 250k без собственного профиля не получает ответ 500k.
2. 500k получает только собственный синтетический профиль.
3. 250k получает собственный синтетический профиль при явно выставленном `frame_count`.
4. При отсутствии 500k-профиля 250k-ответ не подставляется в 500k.
5. 125k request к target 0x50 не получает ни один из 50/250 или 50/500 ответов.
6. CAN_PS на 250k отклоняется J2534-2 ограничением исходного PR #351.
7. Два независимых CAN-канала 250k и 500k имеют собственные ответы.
8. Повтор запроса на одном 250k-канале удаляет старый непрочитанный D2 RX.

Все ответы тестов **синтетические**, не OEM и не свидетельствуют о принятии VIN.
