# B3A276 — экспериментальный структурированный F114, отдельно от A6 Ignition Lab

## Зачем

В оригинальной VIDA, процесс `IEXPLORE.EXE` / лабораторный PID `000036BC`,
на B3A275 выполнены три положительных `22 F1 14` на `0x726`:
`62 F1 14` плюс 17 ASCII-байт VIN; после этого GUI выдал
`The VIN can not be decoded on selected Partner Group`.
В этом сеансе A6 и D2 B9 не отправлялись.

Оригинальная CarCom-схема F114 для одного из исследованных CEM
содержит 166-байтный блок данных с 17-байтным VIN начиная на
**смещении 11 байт** (88 бит). Текущий legacy-ответ помещал
VIN на смещение 0. Предыдущий отдельный B3A261 эксперимент использовал
**неполный 88-байтный** PJB/D2-derived блок, отмеченный в отдельном
лабораторном манифесте как способный обеспечить чтение VIN в одной
VIDA-сессии. Это **не** доказательство правильного OEM F114 для
XC90 V8 MY2009, полного профиля или настоящего автомобиля.

Задача B3A276 — провести строго ограниченный A/B-тест **формата**
и исключить ложное объяснение отказа VIDA только изменением интерфейсной
Partner Group. Никаких OEM байт и VIN в репозиторий не добавлено.

## Только в новой, независимой копии лаборатории

Пример `virtualcar.ini` (не полный INI):

```ini
[Diagnostics]
EnableP3F114StructuredLab=1

[P3F114]
Enabled=1
PayloadHex=<88 hex bytes from the separately retained private lab fixture>
```

Не вставлять заглушку в реальный INI; `PayloadHex` должен быть **полным**
88-байтным локальным буфером, с `57` в первом байте, `0D 0A` в
двух последних байтах, и точным `[Vehicle] VIN` в байтах
**11–27** включительно. Корректная длина не делает образец
подлинным OEM F114. Если обе опции не включены, обработчик выключен;
если включены, но fixture отсутствует/ошибочен, F114 остаётся без
ответа: **не** подменяется legacy 17-байтным ответом.

Обработчик ограничен `ISO15765=6`, 500000 бит/с,
точным `22 F1 14` и **сконфигурированными** физическими парами:

- `0x726 -> 0x72E`, `TxFlags=0`;
- `0x18DA50F1 -> 0x18DAF150`, `TxFlags=CAN_29BIT_ID`.

При допустимой явной конфигурации возвращает 91 байт
`62 F1 14` + ровно 88 байт из локальной fixture, через существующий
J2534/ISO15765 receive/filter path. Нет fallback к 20-байтному
legacy F114 при ошибке опции/адреса/скорости/флагов. Прочие
запросы, включая `F190`, `A6 1A04`, `B9 F0/FB`, `AE 1B`,
`A45F` и `DD02`, используют прежние обработчики.

## Изоляция и критерии

- База ветки — exact-head draft B3A275 `f0004b5fecdac5a8b29caaa245220a52bd6338e0`.
- Отдельная ветка/PR, отдельная DLL, отдельный INI и **новое** имя J2534;
  не перезаписывать рабочую `C:\VirtualCar-CEM-A6-Ignition-Lab`,
  D2 Replay Lab или старую F114 Lab.
- Девять Host C категорий: грамматика, opt-out, ошибочный opt-in,
  exact reply на обоих маршрутах, CAN флаги, wrong DID, response-ID,
  strict filter, 125k и изменение VIN. Это *исходники тестов*, не
  автоматический результат PASS.
- До подтверждения exact-head сборки и нативного x86 smoke **не**
  регистрировать/использовать новую DLL в оригинальной VIDA.
- Для VIDA A/B фиксировать UI Partner Group, исходный/новый
  ответ F114, выбранный скрипт `ReadVin`, вызов `AddVIN` (если
  доступен в оригинальном журнале) и последующую идентификацию
  отдельно. Отсутствие A6 TX не повышать до результата A6.
- Ни один результат в этой ветке не авторизует PIN,
  SecurityAccess, стирание DTC, программирование или подключение
  к физическому CEM.

## Текущая доказательная граница

B3A275 на original VIDA получил три положительных legacy F114,
но UI VIN decode FAILED; B3A275 native A6 2/2 и D2 F0 3/3, FB 13/13
PASS **в отдельном native smoke**. B3A276 код и тесты только
подготовлены; B3A276 exact-head host/native, original VIDA A/B,
ECU ID, T111/T122 NOT TESTED.
