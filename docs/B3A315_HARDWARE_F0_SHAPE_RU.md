# B3A315 — структура Hardware F0 по клиентскому SectorV

## Основание

Прочитан **локально предоставленный** `SectorV.dll` (SHA-256
`424900034caefd4941b11a625bd38a6d025b42016504151b89c5f5a1267309ef`).
Метод `SectorV.PublicClient.Configuration.ClientP2HardwareProtocol::Decode`,
токен `0x060012FE`, проверяет **уже собранное 15-байтовое тело** Hardware
`B9 F0`, а не отдельный восьмибайтовый CAN-кадр.

Зафиксированные проверки клиентского декодера:

1. Длина тела **ровно 15 байт**.
2. Первые **пять байтов имеют корректные BCD-полубайты** (каждый 0–9).
3. Когда байт 5 равен `0x20`, байты 6 и 7 должны принадлежать печатному
   ASCII (`0x20..0x7E` включительно).
4. Если байт 5 не равен `0x20`, эта ветка проверки ревизии не используется.

Метод клиента формирует текстовые значения, но Virtual Car **не должен
экспортировать оригинальный номер CEM, ревизию, VIN и содержимое ECU**.
Бинарная структура клиента — не аутентификация OEM-источника.

## Доработка

В `emulator/src/p2core/p2_cem_router.c` добавлена чистая функция
`p2_cem_inspect_sectorv_f0_body`. Она возвращает только категории
`no_body`, `invalid_length`, `invalid_bcd`, `invalid_revision`,
`structural_candidate_unverified`.

Прежняя функция `p2_cem_validate_sectorv_f0_body` сохранена как булевый
совместимый интерфейс. Никаких ответов `A3/E3`, `B9 E0/F0` и CAN-кадров
новая функция **не формирует**; механизм J2534 и существующая фикстура
B9FB не изменены.

Даже `structural_candidate_unverified` означает только отсутствие
структурного противоречия с данным декодером: происхождение ответа,
успешный сеанс Hardware, номер автомобиля, реальные ECU и данные XC90
V8 MY2009 остаются непроверенными.

## Границы исследований

Публичная документация `MarvinParanoid/VolvoDiagToolkit` подтверждает
общее соотношение сервисов `A3→E3` в захватах V50/P1, но **не содержит
верифицированной фикстуры A3 для XC90 V8 MY2009**. Примеры других
платформ и годов не копируются в конфигурации эмулятора.

Существуют **два разных** клиентских обработчика:
`ClientP2HardwareProtocol` и `CemM30855FIdentification` в
`SectorV.VehicleDiagnostics.dll`; их маршруты и критерии ответа
нельзя смешивать без динамических доказательств.

## Проверки

`python -m unittest discover -s emulator/tests -p "test_b3a315_hardware_f0_shape.py"`

10 чистых C-групп: корректная длина, NULL, недобор, избыток,
старший и младший BCD-полубайты, нижняя и верхняя границы ASCII,
ветка без ревизии, отсутствие изменения данных и безопасный статус.

**Следующий блокер:** для перехода клиента от A3 к E0/F0 нужна независимая
проверенная запись ответа целевого CEM. До её появления Hardware Session
остаётся `NOT_VERIFIED`. Оригинальные исполняемые файлы и приватные
логи в GitHub не размещаются.
