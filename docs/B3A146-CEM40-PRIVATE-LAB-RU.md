# B3A146: приватный синтетический CEM_40/125k (не OEM-профиль XC90)

## Задача и доказательства

Предыдущий нативный host-тест B3A145 владелец выполнил на Windows и прислал маркер
`PASS B3A145 CEM_40: 8 synthetic transport-only host cases` и `TEST_EXIT_CODE=0`.
Точный `git rev-parse HEAD` в том выводе отсутствует, поэтому привязка теста к head SHA PR #347 не подтверждена. Сам транспортный тест не является приёмкой оригинальной VIDA.

В B3A142 найдены 7 запросов CEM_40/B9F0 и 18 запросов CEM_40/B9FB на 125000 бит/с в ограниченном хвосте нативного журнала, без валидных фикстур. В другом, историческом участке есть 104 маркера доставки D2 для CEM_50/B9FB, но это другая шина/адрес и не доказательство успешной идентификации.

В репозитории уже хранится 13-кадровый синтетический эталон **CEM_50/B9FB**:
`emulator/virtualcar-p2-b9fb-lab-vin.ini`. Он основан на публичном примере 2005 года и содержит синтетический VIN. Остальные поля не были восстановлены для MY2009.

## Содержание PR

Добавлены отдельный генератор и 12 офлайн-тестов, без изменений нативной DLL и любых текущих активных INI.

`emulator/tools/build_b3a146_cem40_lab_profile.py` требует локальный файл **vehicle-identity.json** с VIN из 17 допустимых ASCII-символов и ModelYear=2009. Это только проверка формы, не VIN checksum или заводского декодирования XC90 V8.

Генератор специально и **явно** переносит структуру уже синтетического 13-кадрового примера с адреса 0x50 на 0x40, заменяет только адрес на 0x40 и 17-байтовое VIN-поле, сохраняя прочие исторические поля без попыток выдать их за настоящий XC90. Эта **искусственная транспозиция** нужна только для проверки отдельного маршрута J2534 и возможной реакции VIDA; не доказано, что VIDA распознает её как настоящий XC90 V8.

- [D2_40] B9FBFrameCount=13, ResponseId=00800003, StrictRouting=1, кадры 8F/09..4F.
- [D2_50] B9FBFrameCount=0, оригинальные 13 кадра удалены из генерируемого INI во избежание ложной активности по двум адресам.
- [D2_40_B9F0] FrameCount=0 **по умолчанию**.
- При явном `--enable-synthetic-b9f0`: [D2_40_B9F0] FrameCount=2, данные только `SIM-CEM-125`, очевидно не заводской номер. Это отрицательная проверка требований VIDA к содержимому идентификации, не рабочий OEM-ответ.
- [D2_40_B9FC], [D2_50_B9FC] и все неизвестные DTC/AE1B продолжают оставаться без фикстур.

## Запуск на Windows

Из checkout ветки `feature/b3a146-cem40-private-synthetic-lab`:

~~~powershell
py -3 -m unittest discover -s emulator/tests -p test_b3a146_cem40_lab_profile.py -v
~~~

Создать отдельный приватный каталог (не каталог зарегистрированной DLL):

~~~powershell
$lab = Join-Path $env:LOCALAPPDATA 'VirtualCar\OwnerPrivate\B3A146'
New-Item -ItemType Directory -Path $lab -Force | Out-Null
~~~

**Безопасный первый вариант: только B9FB.**

~~~powershell
py -3 .\emulator\tools\build_b3a146_cem40_lab_profile.py --identity-json "$env:USERPROFILE\Downloads\VirtualCar-VIN-MY2009-Apply\vehicle-identity.json" --output (Join-Path $lab 'b3a146-cem40-lab.ini')
~~~

**Второй вариант с B9F0** можно создать отдельно, в новом каталоге, повторив команду с `--enable-synthetic-b9f0`. Имя выходного файла всё равно должно быть `b3a146-cem40-lab.ini`, существующий файл не будет перезаписан.

В отчёт CLI не выводятся VIN, байты кадров и локальные пути. **Сгенерированный INI содержит приватный VIN; не публиковать и не прикладывать к GitHub.**

Генератор использует эксклюзивное создание файла, отказывается писать в `virtualcar.ini` и не меняет реестр, DLL или VIDA. Чтобы провести реальный эксперимент в VMware, требуется отдельный осознанный шаг с резервной копией и закрытой VIDA: проверка установленной/загруженной DLL и рабочей конфигурации должна быть подтверждена оператором до активации. **Этот PR не выполняет активацию.**

## Ожидаемые результаты и границы

- 12/12 synthetic Python unittest: PASS локально при создании PR, exact-head CI отдельно не подтверждён.
- Исходная 13-кадровая форма и синтетическое VIN-поле прошли офлайн-валидацию, исходный донор остаётся неизменным.
- Ответ CEM_40/B9FB, правдоподобность других полей для MY2009, VIDA NETWORK, ReadVin и ECU Identification: **NOT_PROVEN**.
- Текущий последний скриншот VIDA показывает CEM `Not responding`; созданный INI это состояние сам по себе не изменяет.
- Не проводить VIN/PIN/programming/config writes на физическом автомобиле; этот профиль предназначен только для эмуляции в изолированной VMware.
