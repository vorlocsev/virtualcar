# B3A312 — лексический аудит описаний модели XC90 в приватной BaseData

Дата: 2026-11-19. Черновой PR #376. Статус: код и синтетические тесты; этот новый этап ещё **не запущен на исходной базе владельца**.

## Причина

Реальный предыдущий аудит BaseData выполнил exact description match: Engine=B8444S → one, ModelYear=2009 → one, VehicleModel=XC90 → zero; counts=null. Это **не доказывает отсутствие XC90**. Нельзя подменять строку случайным ID или выбирать 43 профиля по совпадению итогового количества.

## Что выполняется

Инструмент emulator/tools/inspect_vida_basedata_model_labels.py открывает только `BaseData.sqlite` в `mode=ro&immutable=1` + `PRAGMA query_only=ON`. Сверяет метаданные экспортёра, фактические обычные таблицы и row counts. Читает не более 10 000 коротких значений `VehicleModel.Description` *только в память* и считает следующие классы:

- точное `XC90`;
- `XC90` в начале как отдельный токен;
- `XC90` как токен в любом месте;
- подстрока `XC90` без требования границы;
- `XC 90` (с пробелами) как токен;
- `XC-90` как токен;
- NULL/пустые описания.

Классы **пересекаются**, их нельзя суммировать; совпадение токена не доказывает, что это именно нужный `VehicleModel.Id`, поколение XC90 или MY2009. Сырой текст, ID, VIN и профильные строки не выводятся; результаты — только фиксированные ключи и количественные значения. Запросов CarCom или сопоставления между базами нет. Скрипт ничего не записывает.

## Windows — команды из корня checkout PR #376

Сначала обновить репозиторий:

    git pull --ff-only

Затем прогнать новые синтетические тесты:

    py -3 -m unittest discover -s emulator/tests -p test_vida_basedata_model_labels.py -v

Только после `OK` запустить на владельческой офлайн-копии:

    py -3 .\emulator\tools\inspect_vida_basedata_model_labels.py --folder 'E:\VirtualCar\VIDA-private'

Если **все** лексические категории нулевые, нужна другая подтверждённая исходной базой таблица или ключ, а не автоматическая замена буквального описания. Если несколько кандидатов, нельзя произвольно выбирать один. Точный модельный ID и 43 профиля не воссоздаются этим инструментом.

Всегда false: `model_identity_resolved`, `cross_database_profile_mapping_verified`, `original_selection_of_43_reconstructed`, `original_vida_readvin_accepted`. Предыдущий точный двигатель/год остаётся отдельным результатом. Оригинальная VIDA, её SQL Server, J2534, CEM и данные пользователя не изменяются.
