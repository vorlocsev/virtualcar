# B3A314 — безопасный аудит Hardware CEM

Цель: сравнить уже записанные события B9FB, исходящих A3/E0/F0 и полученных SectorV результатов Hardware без выдумывания ответов, ключей доступа и аттестации автомобиля.

## Применение

Запускать только на локальных, ограниченных по времени копиях журналов:

    python emulator/tools/audit_b3a314_sectorv_hardware.py --native "C:\local\native-events-REDACTED.txt" --client "C:\local\sectorv-events-REDACTED.txt"

На выходе JSON с фиксированными категориями и числовыми счётчиками. В вывод не включаются VIN, идентификаторы процесса, имя приложения, пути, временные метки, сырые CAN-байты, коды доступа и конфигурация.

## Пределы доказательств

- P2_HW_TX_A3_OBSERVED обозначает исходящий A3, не ответ ECU.
- E0_AFTER_A3_UNVERIFIED и F0_AFTER_E0_UNVERIFIED обозначают порядок TX, не открытую сессию CEM.
- Client hardware-session result=no-reply означает отсутствие принятого клиентом ответа, не доказательство первопричины.
- Staged B9FB означает подготовленную фикстуру, не декодирование VIN.
- Client VIN received означает принятые транспортные кадры, не подлинную идентичность XC90 V8 MY2009.
- Нативные и клиентские журналы не аттестуются как одна сессия; приборы, адаптеры и OEM-файлы не проверяются.

Для старых загруженных отчётов v6 аудит обнаружил: B9FB 0x50 staged=1, клиентский VIN received=1, Hardware 0x50 no-reply=1, 0x40 no-reply=1 и Hardware failure=1. В старой native-выборке метки B3A313 отсутствуют, поэтому подтверждение ответа A3 равно false.

Проверка:

    python3 -m unittest discover -s emulator/tests -p 'test_b3a314_sectorv_hardware.py' -v

10 синтетических тестовых групп. Положительные ответы A3/E3/A6/B9 E0/F0, Security Access, запись ECU, PIN, физический J2534, оригинальная VIDA и полноценная идентификация Hardware этим этапом не реализуются и не подтверждаются.
