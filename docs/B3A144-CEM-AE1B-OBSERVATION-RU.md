# B3A144: CEM 0x40 AE 1B (read-only native observer)

## Основание

Владелец получил \`CEM_40_AE1B_TX=12\` из исторического файла SectorVVirtualCar.log по шаблону \`TX (app request) 00 0F FF FE CB 40 AE 1B\`. Это ровно двенадцать совпадений в журнале, но не подтверждение, что все запросы принадлежат последнему сеансу оригинальной VIDA или тому же J2534-каналу.

В публичном исследовании спроецированной реализации VIDA D2 \`spnda/volvo_vida_db/scripts/d2.py\` сервис \`0xAE\` классифицирован как Read DTC. Применимость конкретного селектора \`0x1B\` и формат правильного ответа CEM XC90 MY2009 этим не подтверждены. Полная оригинальная ответная трасса \`CEM_40/AE1B\` у проекта отсутствует.

Исходник development, \`emulator/src/virtualcar.c\`, до B3A144 распознавал A3/A6 и B9 F0/FB/FC, но \`CB 40 AE 1B\` попадал в \`Unmatched request ID / protocol, no response\` на физическом ID запроса D2 \`0x000FFFFE\`.

## Что делает этот PR

В native \`process_d2()\` добавлена только классификация строго распознанного запроса: протокол CAN, ID \`0x000FFFFE\`, длина сообщения 4..8 байтов, \`CB 40 AE 1B\`, остальные байты равны нулю. Регистрируется маршрут \`CEM\`; при strict routing на скорости не 125000 бит/с результат \`unsupported_bus/no_response\`, на ожидаемой скорости \`unimplemented_probe/no_response\`.

Нет новых ECU-фреймов, нет изменений фильтров, нет изменённого профиля VIN/INI, нет ответов на защищённые команды, нет новых состояний двигателя/зажигания и нет автоматической замены данных из чужих Volvo. Не вызывается \`supersede_d2_exchange\` для нового наблюдателя, чтобы не изменять существующее поведение незавершённых D2-транзакций; это наблюдение, а не реализация DTC.

Неподтверждённые вариации (неправильная цель, сервис, селектор, ненулевая набивка или CAN ID) остаются в прежнем \`UNHANDLED\` маршруте.

## Проверка

В \`emulator/tests/virtualcar_test.c\` расширен существующий нативный host-тест восемью синтетическими сценариями:
1. CEM 40 AE1B, 125000 бит/с, strict;
2. тот же запрос, 500000 бит/с, strict;
3. тот же запрос, 500000 бит/с, non-strict;
4. короткий CAN data length 4 без нулевого заполнения;
5. ненулевая набивка;
6. другой target 0x50;
7. другой аргумент 0x1A;
8. другой CAN request ID.

Все сценарии требуют ровно один маршрут и terminal event, и отсутствие RX кадров. Это код тестов, **не доказательство их выполнения**. Exact-head CI, нативная сборка и оригинальная VIDA пока не проверены.

## Дальше

Получить временно ограниченный приватный журнал оригинальной VIDA с метаданными канала/скорости по AE1B и подтвердить, какие RX/ошибки связаны именно с этим запросом. Затем требуется независимый полный D2 ответ для read-DTC CEM (или сознательно ограниченный синтетический контракт), проверка флагов 29bit, CAN RX-ID и фактической панели NETWORK. Возвращаемый статус CEM остаётся последним подтверждённым \`Not responding\`, пока не будет нового оригинального GUI evidence.
