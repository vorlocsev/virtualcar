# B3A336 — точный путь XML + PID в частном Procmon CSV

В отличие от B3A335 (сравнение уже обезличенных JSON), этот этап
читает **один существующий локальный** Procmon CSV и **один существующий**
diagnostic.config.xml на машине владельца. Сверяет выбранное имя
процесса, указанный PID и полный нормализованный Windows-путь XML.
В отчёт попадают только закрытые категории и счётчики, без исходных
путей, PID, времени, XML, VIN или строк Procmon.

## Применение

На авторизованной изолированной Windows VM при наличии исходных файлов:

    py -3 emulator/tools/audit_vida_procmon_exact_source.py --procmon-csv "EXISTING_PRIVATE_CSV_PATH" --xml-candidate "EXISTING_PRIVATE_diagnostic.config.xml_PATH" --process-name iexplore.exe --pid "OPERATOR_OBSERVED_PID"

Имя процесса выбирается по независимому наблюдению, а не по догадке.
Разрешены только iexplore.exe, java.exe, vidamonitor.exe и w3wp.exe.
Сценарий не запускает VIDA/Procmon/J2534, не сканирует диск,
не меняет реестр, DLL или конфигурацию. Оригинальные файлы не
копируются в GitHub/CI. CSV ограничен 32 MiB и 300 000 строками;
XML проверяется существующим B3A332-парсером (128 KiB, без DTD/ENTITY).

## Строгая интерпретация

ReadFile SUCCESS для точного PID и пути подтверждает лишь такое
совпадение **в выбранном CSV**. CreateFile → ReadFile для той же пары
не удостоверяет один Windows HANDLE. Отчёт также различает чтения
других файлов тем же PID и выбранного файла другим PID.

Повторно используемый PID, отфильтрованный или изменённый по порядку
CSV, псевдонимы путей, reparse points и изменившееся содержимое XML
не исключены. Проверяется совпадение строк после нормализации,
а не фактическая идентичность байтов прочитанного клиентом XML.
Содержимое XML сейчас даёт только *candidate* DiagnosticConnection.
Даже успешный ReadFile не доказывает применения NoCommConnection
или J2534DiagnosticConnection в оригинальной VIDA.

Не удостоверяются оригинальность исполняемого файла VIDA,
момент запуска процесса, совпадение окна с B3A333 module snapshot,
выбор GetScript(ReadVin), фактические J2534 TX/RX, принятый VIN
или идентификация ECU. Все соответствующие флаги остаются false.

Следующий шаг: независимая проверка личности процесса, времени
экспорта и реального пути/содержимого файла в одном сеансе, затем
проверка скриптового потока и GUI приёмки. Это не разрешение
менять оригинальную VIDA или подставлять CEM A3/A6/B9F0 ответы.
