# VIDA: работа с оригинальными данными без обезличивания

Решение для дальнейшего анализа: **сохранять исходные названия баз,
схем, таблиц, колонок, идентификаторы и значения записей**. Исследователь
может изучать реальные связи CarCom → ECU Profile → InitHw → GetScript,
а не делать выводы только по обезличенным счётчикам.

Новый `emulator/tools/vida_original_table_reader.py` выполняет
**явно запрошенное владельцем, локальное, только читающее извлечение
одной исходной таблицы SQL Server**. Это не изменение баз и не запуск
VIDA или J2534.

## Что сохраняется без маскирования

- Оригинальные имена базы, схемы, таблицы и колонок, регистр и Unicode
- SQL-типы и идентификаторы колонок из `sys.columns`
- Значения строк, включая исходный текст и `NULL`
- Бинарные значения в обратимом представлении Base64
- `decimal` как десятичный текст, `float` как Python IEEE-754 hex,
  даты/время как ISO-8601 и GUID как hex

**Ничего из этого не подменяется маркерами SECRET, HASH, REDACTED
или случайными идентификаторами.** JSON сохраняет значения в том виде,
в котором их вернул ODBC-драйвер. Драйвер может менять точность или
представление некоторых SQL-типов. Поэтому поле
`raw_sql_server_type_roundtrip_verified` остаётся `false`:
полную побайтовую эквивалентность исходной MDF это не доказывает.

Для неподдерживаемых типов или превышения ограничения строк утилита
возвращает ошибку, **не создавая частичный успешный результат**.

## Чтение оригинальной таблицы в Windows VMware

Требуются установленный `pyodbc`, проверяемый сертификат SQL Server,
DSN с интегрированной Windows-аутентификацией и реально ограниченная
учётная запись SQL Server с правами чтения. `ApplicationIntent=ReadOnly`
не является механизмом контроля прав.

PowerShell, из проверенного checkout PR #317:

```powershell
$env:VIDA_SQLSERVER_DSN = 'VIDA_READONLY'
$private = Join-Path $env:USERPROFILE 'VIDA-original-private'
New-Item -ItemType Directory -Force -Path $private | Out-Null

py -3 emulator/tools/vida_original_table_reader.py `
  --database CarCom `
  --schema dbo `
  --table T161_Profile `
  --max-rows 1000 `
  --output (Join-Path $private 'CarCom-T161_Profile-original-001.json')
```

Здесь `T161_Profile` только **исследовательская гипотеза**,
заимствованная из старых опубликованных сведений о структуре CarCom.
Наличие этой таблицы в конкретной VIDA 2015A **не подтверждено**.
При отсутствии таблицы утилита завершится ошибкой. Для другой таблицы
укажите её настоящее имя, полученное из вашей установки.

`--max-rows`: 1–5000, по умолчанию 1000. Если строк больше лимита,
завершение с ошибкой, без усечения с пометкой об успехе.
Максимальный размер JSON 50 МиБ; файлы создаются только как новые
и за пределами checkout. На POSIX создаются с правами 0600.
На Windows проверьте ACL закрытого каталога.

## Что меняется в методологии проекта

Полноформатные исходные данные используются для исследования.
Старые `vida_*redacted*` инструменты остаются **только для обратной
совместимости** с существующими 17 статическими gate и при необходимости
для обмена минимальными сводками. Их обезличенные отчёты не заменяют
анализ оригинальных имён, строк и значений.

Никакой автоматической отправки исходных записей в GitHub, CI,
комментарии PR или релизные артефакты. Это вопрос места хранения, а не
обезличивания: **полные значения остаются полными** на локальной
машине владельца. В исходный код GitHub добавляется только сама
утилита и синтетические тесты.

Для `DiceTiming` допустимо затем выбирать настоящие таблицы по
именам, найденным в оригинальной базе, и извлекать их значения,
включая реальные тайминги, но до подключения оригинальной базы
их значения и связь с `InitHw` не установлены.
