# B3A318 — XC90 V8 MY2009: варианты CEM и реальные запросы B9F0

**Статус источников:** read-only исследование. Это не ответ OEM CEM, не
доказательство принятых VIN, Hardware Session, part number или ECU identity.

## 1. Новая применимость: строго отдельно от живой диагностики

Публичная сторонняя матрица диагностического покрытия DriveRAP для
**XC90 2009 B8444S (EU)** содержит:

| Блок | Номер в матрице | Диагностическое семейство |
|---|---|---|
| CEM | `31296075 AA` | `D2 v7` |
| CEM | `30682825 A` | `GGD v2` |
| ECM Denso CV8 | `30670321 AA` | `GGD v2` |

Источник:
https://widnesautoelectrical.co.uk/wp-content/uploads/2019/02/DriveRAP-VOLVO-web-1.pdf

Запись CEM D2 повторяется в исходнике; здесь дедуплицирована. Это
**матрица совместимости диагностического оборудования**, а не VIN-специфичный
факт об установленном блоке, записанный оригинальной VIDA обмен или ответ
`A3 02`. Нельзя выбирать D2/GGD автоматически либо приравнивать
GGD-ответ ECM к D2 B9F0.

Дополнительный независимый по типу источник — дискуссия сообщества:
https://www.matthewsvolvosite.com/forums/viewtopic.php?p=589738 .
Автор относит `31296075` и `30682825` к кандидатам CEM-X (P2 CEM-L/H),
но прямо не различает CEM-L и CEM-H. Это не OEM-аттестация.

Источник кандидатов:
`emulator/tools/data/b3a318_xc90_v8_cem_candidates.json`.
Ни одна запись не разрешает генерировать ответ ECU.

## 2. Клиент SectorV: существуют два разных обработчика

Предоставленная пользователем `SectorV.VehicleDiagnostics.dll`,
SHA256 `0cf6993b3ea33dcbf50b136d1d13b59a59c1bce35533067c62e0d40813e595b5`,
исследована *статически*, без запуска.

В `CemM30855FIdentification.<ReadCore>g__WaitForSessionConfirmation|7_1`
(токен `0x06000087`) проверяется:

- кадр на кандидатном CAN ID `0x01200003`;
- восемь байтов CAN payload;
- первые **четыре** байта сравниваются с **`CB 50 E3 02`**;
- deadline 5000 мс.

Перед этим `ReadCore` использует встроенный запрос
`CF 50 A3 02 03 A5 A5 00`.

**Это условие конкретного парсера клиента**, а не доказанная трасса
от подлинного CEM MY2009 и не авторизация реального автомобиля.
Отдельный `ClientP2HardwareProtocol` — другая реализация, их
условия нельзя объединять. Существующие client-логи `P2 hardware-session RX v3`
не удостоверяют, что вызывался именно путь M30855F.

Оригинальные DLL, IL и непроверенные положительные ответы в GitHub
не размещаются. Новый код не обходит Security Access и не генерирует E3.

## 3. Повторный анализ загруженного Hardware Metadata

Из ранее загруженного владельцем `B3A285-Hardware-Metadata.txt`
новый локальный анализатор выделил **четыре группы нативного логгера**:

| Группа логгера | B9F0 запросов | Разных адресов | No recorded ECU fixture | A3/A6 unimplemented |
|---:|---:|---:|---:|---:|
| 1 | 6 | 6 | 6 | 1 |
| 2 | 19 | 19 | 18 | 3 |
| 3 | 0 | 0 | 0 | 0 |
| 4 | 0 | 0 | 0 | 2 |

Это корректирует чрезмерно общий старый вывод «до ECU identification
SectorV не дошёл»: **опытные запросы B9F0 к нескольким ECU наблюдались**.
При этом `no fixture` и сам TX не означают принятую идентификацию;
отдельные process-prefix группы не связаны достоверным session ID.
PID может повторно использоваться ОС, поэтому группа — не доказанная
сессия автомобиля.

Применение локально, без передачи приватных исходных журналов:

    python emulator/tools/audit_b3a318_p2_ecu_requests.py --native "C:\path\to\B3A285-Hardware-Metadata.txt"

JSON содержит только условные номера групп, адреса D2, baud, счётчики
и флаги NOT_VERIFIED. Нет VIN, PID, CAN payload, ключей доступа, путей или
исходных флагов TX.

## 4. Тесты и ограничения

`python -m unittest discover -s emulator/tests -p 'test_b3a318_p2_ecu_requests.py' -v`

15 синтетических групп проверяют: шесть адресов B9F0, независимые группы,
повторы, отдельные B9FB/A3, ошибочные префиксы/метаданные,
лимиты размера, безопасность приватных значений, раздельные скорости
и узлы, запрет ложного ECU PASS, CLI без вывода пути и отсутствие
объединения CEM D2 / CEM GGD / ECM GGD.

Никаких изменений J2534 DLL, VIN-фактического профиля, SectorV/VIDA,
оригинального INI, Security Access, ECU-перепрошивки либо физического CEM.

**Следующий критерий приёмки:** один непрерывный, разрешённый,
только читающий клиентский/нативный сеанс с указанием,
какой обработчик действительно используется, какие сети/ID/фильтры
настроены, какой ответ выдан клиенту, и что именно SectorV принял.
До появления этого доказательства — Hardware Session и ECU ID
остаются NOT_VERIFIED.
