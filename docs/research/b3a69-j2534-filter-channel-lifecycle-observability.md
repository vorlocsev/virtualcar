# B3A69: наблюдаемость жизненного цикла J2534-фильтра (source-only)

## Факты, предшествующие изменению

В отчёте владельца B3A68 для одного зафиксированного `D2 0x40 B9 FB` при 125000 в старом нативном журнале: 35 полных пар фильтр/маска/шаблон, включая 7 PASS с odd-ID маской, потенциально пропускающих **синтетический** лабораторный CAN ID. В окне до запроса также 4 успешных `CAN_PS` подключения при 125000, но разные типы подключений и 28 FLOW фильтров. Исходный `PassThruStartMsgFilter` старого C-кода не записывал **идентификатор канала**, а `PassThruStopMsgFilter` не записывал факт снятия. Поэтому B3A68 не мог достоверно привязать PASS к CAN_PS каналу запроса; 7 подходящих масок не доказывают, что VIDA получила ответ.

## Добавляемые журнальные события, без изменения семантики J2534

Только исходник `emulator/src/virtualcar.c` (публикуется **без готового DLL или автоматической установки**):

1. `J2534 filter accepted channel/type/id/protocol/baud (BE)` — **20 байт, пять uint32 Big Endian**. Регистрируется только после того, как существующий обработчик добавил фильтр. Поля: channel id, filter type, filter id, клиентский protocol id (CAN_PS сохраняется как `0x8004`), baud bps. Имя события намеренно отличается от старого `PassThruStartMsgFilter type / id (BE)`, которое сохраняется.
2. `J2534 filter stopped channel/id (BE)` — **8 байт**, два uint32 BE; только после успешного удаления фильтра. Неудачная попытка Stop не считается снятием.
3. `J2534 native strict RX filter policy (BE)` — **4 байта**, uint32 BE, значение фактически загруженного `g_strict_j2534_filters` на момент инициализации. Это не означает, что исходная VIDA использовала или приняла этот фильтр.

Существующие записи `  filter mask`, `  filter pattern`, `TX context channel/protocol/flags/baud/time-us (BE)`, `PassThruDisconnect channel (BE)`, `PassThruClose`, `P2 D2 request target/opcode/baud/flags (BE)` и `RX context ...` остаются без изменений.

**Граница доказательства:** даже при новом двоичном логе необходимо проверять непрерывный процессный epoch (PID может повторно использоваться), один канал, тот же передающий context, верный протокол/скорость, событие Stop/Disconnect/Clear, и подтверждённый RX. Поиск VIN и OEM CEM не выводится из одного фильтра.

## Безопасный путь проверки

- Пока этот PR не собран и не опубликован в отдельный тестовый артефакт, **новых событий в существующем журнале быть не может**. Нельзя требовать от владельца B3A45 или B3A68 найти их задним числом.
- Изолированная лабораторная проверка B3A65–B3A67 уже демонстрировала 13/13 CAN_PS RX только для отдельного синтетического профиля. Она **не подтверждает** работоспособность нового C-кода.
- Для acceptance нового патча нужны исходный статический diff-review, x86 сборка, нативные regression-тесты фильтров PASS/STOP, проверка формата 20/8/4 байт, а затем новый B3A45 baseline и окно теста. Не переиспользовать прежний baseline для оценки нового сеанса.
- Нет разрешения вносить этот код в установленный драйвер VIDA: без отдельного решения не менять зарегистрированный DLL, `Registry32`, активный `virtualcar.ini`, оригинальную VIDA/SQL или физический J2534.
