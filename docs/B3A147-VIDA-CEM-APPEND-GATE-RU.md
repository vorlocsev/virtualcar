# B3A147: безопасная проверка CEM D2 за один контролируемый запуск VIDA

## Цель

В нативном журнале VirtualCar уже зафиксированы запросы CEM_40/B9F0, CEM_40/B9FB и 12 исторических TX совпадений CEM_40/AE1B. Но они взяты из различных исторических окон, и их нельзя смешивать в одну успешную или неуспешную сессию.

Существующий read-only инструмент `emulator/tools/audit_vida_j2534_session_window.py` умеет делать базовую отметку двух журналов до ручного запуска оригинальной VIDA и анализировать только новые строки после него. B3A147 расширяет его строго категориальными счётчиками по сервисам:

- CEM_40 и CEM_50: B9F0, B9FB, B9FC, AE1B.
- Глобальные события native D2: staged, delivered, отсутствующая фикстура, отсутствующий target, несовпадение шины, фильтр, AE1B unimplemented/wrong bus.
- Отдельный счётчик ненулевого хвоста за объявленной длиной `CB`. В D2 такой остаток не является автоматической ошибкой.
- Все значения в JSON суммарные; не включают raw CAN ID, кадры, VIN, host PID, пути, SQL или приватные строки.

**Не выполняет** управление VIDA/J2534, загрузку или подмену DLL, редактирование INI, создание ответа CEM и запись/очистку кодов ошибок.

## Почему этого недостаточно для признания VIDA

Native `TX (app request)` может принадлежать не VIDA. Native `P2 D2 delivered` означает выдачу в `PassThruReadMsgs`, но не распознавание VIN клиентом. Суммарные staged/delivered относятся ко всему ограниченному окну, а не к определённому `CB 40 B9 FB`; здесь не выполняется атрибуция `channel/generation` к запросу. Для окончательной приёмки требуются доказательства загруженной DLL, корректного GUI-состояния и фактического результата ReadVin / T111 / T122.

## Как проверить на владельческой VMware

В доверенной локальной копии этого PR выбрать фактические файлы журналов самостоятельно: **путь VIDA лога не следует выводить из одного лишь `E:\vida`**, и путь native `SectorVVirtualCar.log` также требуется проверить. Скрипт не ищет их по диску и не копирует.

1. Остановить прежние диагностические клиенты и выбрать существующие журналы по фактическому расположению.
2. Создать приватную папку вне репозитория, например `%LOCALAPPDATA%\VirtualCar\OwnerPrivate\B3A147`.
3. Запустить `baseline` до ручного NETWORK UPDATE:

~~~powershell
py -3 emulator/tools/audit_vida_j2534_session_window.py baseline --vida-log "$vidaLog" --virtual-log "$nativeLog" --private-baseline "$privateDir\baseline.json"
~~~

4. В запущенной оригинальной VIDA выполнить один обычный read-only NETWORK UPDATE, снять скриншот CEM и при необходимости ReadVin. Не программировать физические ECU.
5. Запустить `delta`:

~~~powershell
py -3 emulator/tools/audit_vida_j2534_session_window.py delta --vida-log "$vidaLog" --virtual-log "$nativeLog" --private-baseline "$privateDir\baseline.json" --output "$privateDir\delta.json"
~~~

6. Прочитать `cem_d2_append_window` в приватном `delta.json`. Для публичного статуса можно сообщить только категории и счётчики, без приватных логов и исходных кадров.

Если лог был перезаписан, очищен или изменил ранее существовавшие байты, инструмент отклоняет delta. Он не пытается угадывать или соединять несопоставимые исторические окна.

## Регрессии и границы

Добавлены восемь синтетических тестов (09–16) к имеющимся восьми: четыре команды CEM40, изоляция CEM50, чужие ID/адреса, битые строки, ненулевой хвост, независимые native маркеры, отсутствие ложного VIDA-подтверждения, секреты не выходят в JSON.

`python -m unittest discover -s emulator/tests -p test_audit_vida_j2534_session_window.py -v` должен выполнить все 16 сценариев. **Exact-head CI и запуск на original VIDA не подтверждены до фактического отчёта.** Этот PR не заменяет draft #346–348 и не требует их слияния.
