# B3A141: статический аудит CEM D2 B9F0 (только чтение)

Цель: не выдавать демонстрационные кадры другого Volvo за ECU-идентификацию XC90 V8 2009. Анализируются только секции D2_40_B9F0 (125000 бит/с) и D2_50_B9F0 (500000 бит/с) локального INI. Никакие кадры не генерируются, адаптер J2534/VIDA не вызывается, рабочий INI не изменяется.

Код проверен относительно emulator/src/virtualcar.c: в B9F0 FrameCount с ключами Frame0..Frame3F, а ResponseId задаётся шестнадцатеричным CAN ID. B9FBFrameCount не применяется к B9F0. В многокадровом ответе проверяются 8F/97 ... F9 F0, номера продолжения, промежуточные 50..57, допустимое повторение начального кадра после маркера субблока и завершающий 48..4F. Форма/количество кадров не доказывают правильность OEM-данных и ответа VIDA.

Публичная гипотеза: в чужих Volvo CEM на CAN-LS для CB 40 B9 F0 отмечены CAN ID 0x00600005 и начало 8F 40 F9 F0 (например, https://github.com/vtl/volvo-cem-cracker/issues/36). Это не измерение XC90 V8 2009 и не основание подменять ResponseId в действующем INI. Native default для CEM 40: 0x00800003. Оба кандидата требуют отдельной проверки фактических VIDA-фильтров и J2534-флагов.

## Запуск

Из корня checkout:

~~~powershell
py -3 .\emulator\tools\audit_vida_b3a141_d2_b9f0.py --ini "$env:LOCALAPPDATA\VirtualCar\B3A135D-VIDA-2315c745dfb3\virtualcar.ini"
py -3 -m unittest discover -s emulator/tests -p test_audit_vida_b3a141_d2_b9f0.py -v
~~~

Ответ JSON выводит только классы, числа кадров и статус доказательств. Никогда не экспортируются VIN, PID, пути, байты ответа или сам ResponseId. При ошибке чтения выводится только общая категория без приватных данных.

## Границы

- structural_positive_not_oem_verified: локальная форма совпадает с validate_d2_fixture; не означает правильную аппаратную/программную идентификацию.
- missing_terminal_frame: неполный многокадровый ответ; не устанавливать в рабочую VIDA.
- cross_vehicle_capture_candidate_not_xc90_proven: идентификатор встречался в другом автомобиле, применимость к XC90 и RX-фильтру не проверена.
- Не утверждать успешный ReadVin, CEM identification, T111/T122, загрузку DLL или реальные ECU RX по одному статическому отчёту.

Следующее действие после независимой записи полного проверяемого ответа B9F0 конкретного виртуального CEM: проверить транспорт, RX фильтр, тайминги, CLEAR_RX_BUFFER и фактический результат DIAGNOSTICS -> NETWORK. Для B9FB существует другой маршрут и другой валидатор, смешивать их нельзя.
