## Проверка статической интеграции

Все **14/14** unified-diff hunks из PR #350 применились к исходному файлу `virtualcar.c` PR #351 с **единственным точным совпадением контекста для каждого фрагмента**. Эти же изменения при применении к общей базе воспроизвели файл C PR #350 побайтно. Остальные 16 файлов PR #350 перенесены по проверенным SHA blob, без ручной модификации содержимого.

Это не заменяет компиляцию C/Windows, host native ABI, интеграционные регрессии и GUI приёмку.

## Область и границы

Изменения объединяют виртуальный транспорт J2534-2 и локальные CEM D2 lab fixtures, но **не добавляют OEM-неподтверждённые ответы** `A45F`, `DD02` и не объявляют успешное обнаружение XC90 V8 MY2009.

Генератор B9FB v4 использует private VIN и заполняет chassis как последние шесть цифр VIN, а пять BCD-байтов номера документа и двубайтовое поле factory зануляет. PNR-3=`000`, FYON и другие значения остаются синтетическими заглушками. Соответствие исходной VIDA CarCom разметке VIN 11/17 байт подтверждено, но 88-байтный lab B9FB **не является проверенным OEM** ответом на весь FB (CarCom reference 166 байт).

На оригинальной VIDA в отдельном прежнем сеансе зафиксированы запросы ISO15765/500000 без доставленных ответов, в частности `0x18DA50F1`, `0x18DA10F1`, с DID A45F/DD02. Эти запросы данным переносом не исправлены.
