Virtual Car dev46 — лабораторная сборка прокси, без релиза

Используйте артефакт VirtualCar-dev46-lab-x86 из успешного запуска GitHub Actions.
Он появляется после сборки и проверки настоящей загрузки DLL в Windows x86.
Тесты выполняются с синтетической DLL; VMware и реальный автомобиль не проверены.
Точный коммит сборки и SHA-256 каждого файла указаны в manifest.json.

1. Распакуйте сборку в отдельную папку внутри лабораторной Windows/VMware.
2. Запустите SectorV-Trace-OneClick-v0.3.6.7-dev26.exe.
   Прежнее имя файла и название адаптера dev26 сохранены; внутри новая схема 46.
3. Выберите уже установленный SectorV и исходную VirtualCarJ2534.dll.
   Исходная DLL не входит в эту сборку. Не переименовывайте и не заменяйте её.
4. Нажмите «Начать». В SectorV выберите «VirtualCar Trace VM dev26»,
   выполните только чтение VIN/CEM и закройте SectorV.
5. Сохраните новый j2534-trace-*.jsonl из папки
   %LOCALAPPDATA%\VirtualCar-Trace-OneClick\dev26\logs.
   Детальная диагностика ISO15765 находится в записях schema 46.
   Отчёты на рабочем столе пока используют прежнюю schema 15.

OneClick создаёт отдельную регистрацию адаптера трассировки и не подменяет
регистрацию исходного адаптера. Параметры DLL/журнала задаются только процессу
SectorV. Для регистрации может потребоваться подтверждение Windows.
Если OneClick сообщает о конфликте существующей регистрации dev26,
он не перезаписывает её; сохраните сообщение для разбора конфликта.

Что проверить по журналу:
- работает ли прежний B9FB и доставляются ли 13 кадров;
- какой FLOW_CONTROL_FILTER установлен перед каждым ISO15765 TX;
- есть ли RX на том же канале и какие кандидаты сопоставления указаны;
- сколько времени прошло до снятия фильтра без финального RX.
Сопоставление не доказывает принятие VIN клиентом или внутренний ECU timeout.

Не добавляйте приватные INI, оригинальную DLL, донорские данные или дампы
в репозиторий и артефакты. Подробности: DEV46_PROXY_RU.md.
