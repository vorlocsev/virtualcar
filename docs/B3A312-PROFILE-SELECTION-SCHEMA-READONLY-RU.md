## Границы

Скрипт проверяет \`_vida_meta\`, \`_vida_tables\`, \`_vida_columns\`
в двух локальных экспортных SQLite-файлах. Открытие:
\`mode=ro&immutable=1\`, \`PRAGMA query_only=ON\`, запрет WAL/SHM/journal
sidecars, ограничение размера каталога. Запросы не обращаются к
пользовательским строкам таблиц; имена таблиц/столбцов выдаются только
для ограниченного множества кандидатов по лексическим категориям profile,
vehicle, model, engine, variant и т.п. Это исходные имена схемы, не значения.

Вывод: JSON \`metadata_only\`, найденные схемные имена, количество
подходящих таблиц, флаги усечения и \`source_rows_read=false\`.
**Никакие исходные profile.identifier, VIN, SQL-поля со значениями или
приватные записи не выводятся.** Нет записи на диск, экспорта или
изменения VIDA/SQL/INI.

**Это не доказательство 43 профилей, не подтверждение отношения BaseData ↔
CarCom, выбора профиля приложением VIDA, D2/GGD или принятых VIN/ECU.**
Сначала по реальным столбцам выбрать и независимо проверить SQL-предикат
оригинального сопоставления. Если критерий не удаётся восстановить,
пометить 43 профиля как неподтверждённую для воспроизведения выборку,
а не заполнять входные файлы случайными строками.

Проверка офлайн-копий и оригинального SQL Server остаются разными
acceptance gates. Оригинальную VIDA, файлы источников и приватные
профили в GitHub/CI не отправлять.


## Фактический запуск владельца (2026-11-19)

Владелец обновил PR #376 до `53962e5` и выполнил метаданные
на исходных офлайн SQLite-копиях. Получен `status=metadata_only`,
`source_rows_read=false`, `CarCom.catalog_table_count=51`,
`BaseData.catalog_table_count=23`; всего 11 / 13 таблиц-кандидатов по
лексическому фильтру. Это фактическое подтверждение доступности **схемы**
обеих баз, не доказательство 43 профилей.

**Схема BaseData:** `VehicleProfile` содержит `fkVehicleModel`,
`fkModelYear`, `fkEngine`; связанные справочники `VehicleModel`,
`ModelYear`, `Engine` имеют `Id` / `Cid` / `Description`.
`AMYProfileMap` содержит `fkSourceProfile` / `fkTargetProfile`;
`VINDecodeModel` / `VINDecodeVariant` — отдельная ветка
описания VIN. Эти столбцы пока не являются проверенными строковыми связями.

**Схема CarCom:** `T161_Profile` содержит
`fkT162_ProfileValue_Model`, `_Year`, `_Engine` и
`identifier`; `T162_ProfileValue` содержит `id`,
`identifier`, `fkT163_ProfileValueType`; `T160_DefaultEcuVariant`
содержит `fkT161_Profile` / `fkT100_EcuVariant`.
Совпадение названий сущностей и даже итогового числа 43 **не подтверждает**
связь BaseData ↔ CarCom: требуется ограниченный параметризованный
проверочный подсчёт на реальных строках, без вывода оригинальных значений.

Первый реальный Windows `py -3` запуск тестов: **1/8 PASS,
7 ERROR** на удалении тестовых временных SQLite файлов с `WinError 32`.
Причина: `with sqlite3.connect(...) as db:` не закрывает соединение,
а только завершает транзакцию. Проблема устранена в тестовом файле
явным `contextlib.closing(...)` для всех 7 подключений. Это
регрессия **тестовых фикстур**, не ошибка чтения приватных данных;
сама метаданные-проверка завершилась успешно.

После фикса требуется повторный запуск полного набора восьми тестов
на Windows 3.15; до отчёта владельца его результат **НЕ ПРОВЕРЕН**.
